# Kasha — спецификация дизайна для разработки

Версия документации: **1.0, 13 сентября 2026**. Статус: **целевой дизайн и комплект передачи в разработку**. Наличие требования или ассета здесь не означает, что оно уже реализовано в приложении.

Этот комплект соединяет три источника: актуальные исходники Kasha, два выбранных пользователем рисунка и каноническое UX/UI-ТЗ из разделов 0–44. Дополнительно учтено уточнение пользователя об анимированных собственных иконках и фоне с очень тёмной макросъёмкой гречки исключительно для сплеш-экрана.

**Цель:** спокойное, взрослое, узнаваемое приложение для голоса и мыслей. Тёплая светотень, точная типографика, один выразительный объект записи и понятные состояния должны работать в настоящем приложении, включая ошибки, длинный текст, клавиатуру и увеличение шрифта.

## Приоритет требований

1. Новые прямые указания владельца продукта, включая разрешение макрофона с гречкой.
2. Этот пакет — источник **целевого UX и визуального дизайна**. Он уточняет и заменяет прежние дизайнерские формулировки, например Commissioner → Geologica.
3. [Общее ТЗ продукта](../SPEC.md) — источник архитектурных, предметных и privacy-инвариантов. Дизайн не отменяет единое Core, local-first, сохранность данных и независимые AI-роли.
4. [Карта репозитория](01-repository-map.md) — описание фактической реализации на зафиксированных ревизиях, а не отдельный источник желаемого внешнего вида.
5. Рисунки — визуальные ориентиры. Они не добавляют функций и не отменяют явно записанные правила.

Если целевой UX требует изменения Core или адаптера, это отмечено в [плане внедрения](11-implementation-plan.md). Нельзя объявлять требование выполненным, добавив внешний вид поверх неработающего действия.

## Что означает готовый дизайн

Готовый дизайн включает не только красивую Главную: все нужные экраны и состояния определены, данные не теряются при переходах, действия доступны с клавиатурой и screen reader, цвета проверены на реальных поверхностях, анимация сообщает состояние и отключается при снижении движения. Пустой экран, отказ разрешения и ошибка сохранения должны выглядеть так же осмысленно, как основной сценарий.
