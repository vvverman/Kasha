# 03. Kasha UI: компоненты и контракты взаимодействия

Этот документ задаёт целевую библиотеку компонентов приложения. Цвета и типографика — в [основах](./02-foundations.md), адаптация и доступность — в [правилах платформ](./07-adaptive-accessibility.md), графика и движение — в [спецификации отрисовки](./08-graphics-motion.md). Поведение конкретных экранов описано в документах [записи](./04-capture-player.md), [контента](./05-projects-notes-tasks.md) и [настроек](./06-settings-privacy.md).

Нормативность: «должен» — условие приёмки; размеры без специальной оговорки — логические dp, размеры текста — sp. Приведённая высота интерактивного элемента является минимальной. Увеличение текста не должно обрезать подпись или закрывать действие. Все компоненты работают в обеих темах.

## 2. Общий контракт компонента

### 2.1. Состояния

Для интерактивного компонента должны быть определены `enabled`, `pressed`, `hovered`, `focused`, `selected/checked`, `busy`, `error`, если они имеют смысл для его роли. Не создавать перечисление, в котором `selected` исключает `focused`: выбранная строка может одновременно быть в фокусе.

Порядок отрисовки:

1. Базовая поверхность и состояние selected/checked.
2. Локальный hover/press слой; он не скрывает selected.
3. Содержимое и индикатор busy.
4. Независимый focus indicator.
5. Ошибка/пояснение снаружи основной геометрии.

Disabled выключает обработчики и haptic, сохраняет размер. Busy блокирует повтор текущей команды, сохраняет её место и подпись; общая навигация остаётся доступной, если это не противоречит конкретной операции. Полупрозрачность отключённого элемента не используется для readOnly.

### 2.2. Обязательные свойства

| Свойство | Правило |
|---|---|
| Имя | Одно смысловое имя: «Начать запись», а не «Микрофон» |
| Роль | Button, Tab, Switch, Checkbox, RadioButton, Adjustable или TextField по фактической функции |
| Значение | Для switch, radio, task completion, slider и playback position доступно программно |
| Фокус | Один предсказуемый focus stop на простую команду; декоративный glyph отдельно не фокусируется |
| Target | 48 × 48 предпочтительно; абсолютный минимум 44 × 44; соседние цели не пересекаются |
| Событие | Одна активация вызывает одну доменную команду; двойное нажатие не создаёт дубликат |
| Busy | Не менять ширину кнопки; озвучивать «Сохраняем»/«Начинаем запись» только при смене этапа |
| Ошибка | Понятный текст и доступный способ повторить; введённые данные не исчезают |
| Клавиатура | Enter/Space активируют кнопку; текстовые поля сохраняют собственную семантику Enter |
| Указатель | Hover не запускает команду и не меняет пользовательские данные |
| Уменьшение движения | Scale/translation/spring отключаются; состояние всё равно различимо |

## 3. Поверхности, разделители и focus

Три визуальных уровня: Canvas, Surface, Floating Surface. Токены Surface Low/High/Highest описывают варианты этих уровней, а не разрешение строить множество вложенных карточек.

`KashaPanel` объединяет связанную группу. Внутри используются интервалы и hairline. `KashaListCard` становится общей строковой оболочкой с режимами `plain`, `grouped`, `standalone`, сохраняя один стиль состояний. Строка внутри Surface не получает ещё одну Surface без смысловой необходимости.

Декоративный hairline из базового ТЗ не является границей доступности. Если форму пустого контрола невозможно распознать по подписи и поверхности, использовать контрастный alias для функционального контура из foundations. Контур поля, checkbox и focus должен иметь проверенный non-text контраст; не повышать яркость всех декоративных разделителей ради этого.

Focus ring рисуется поверх hover/pressed, не меняет layout и остаётся видимым на Accent, Surface и Canvas. При `focus-visible` мышью можно не показывать клавиатурный ring, но ввод с клавиатуры всегда включает его. Ошибка может иметь локальный error contour, focus при этом сохраняет свою внешнюю геометрию.

## 4. Кнопки

### 4.1. Варианты

| Вариант | Поверхность | Содержимое | Применение |
|---|---|---|---|
| Primary | Accent | On Accent; обязательный контраст AA | Начать запись; сохранить подтверждённый результат; главное действие формы |
| Secondary | Surface High в dark; соответствующая поверхность light | Text Primary, hairline | «Привести в порядок», альтернативная конечная команда |
| Quiet | Нет постоянной заливки | Text Secondary | Назад, отмена локального режима, необязательное действие |
| Icon quiet | Нет или слабая локальная поверхность | Text Primary/Secondary по важности | Назад, меню, добавить в заголовке |
| Icon filled | Primary или Surface High | Контрастный glyph | Play/Pause, ключевая локальная команда |
| Destructive | Спокойная Surface; error text alias | Delete + точный глагол | Подтверждённое удаление; не окрашивать экран красным |

Светлая тема имеет собственный On Accent: тёмная надпись на тёмно-коричневом Accent недопустима. Требования к точным парам — в foundations.

На одном участке экрана не больше одной доминирующей Primary. Команды «В заметки» и «В задачи» доступны как две отдельные кнопки, без Note/Task switch. Конкретная иерархия и адаптация пары — в [сценарии результата](./04-capture-player.md). Обе кнопки должны явно сохранять единичную сущность, а не обещать автоматическое разбиение текста на несколько задач.

### 4.2. Состояния

| Состояние | Визуальное изменение | Поведение |
|---|---|---|
| Default | Базовые токены | Нормальная активация |
| Hover | Слабое изменение светлоты поверхности | Без свечения вокруг всей кнопки; без haptic |
| Pressed | Scale0.98 визуального слоя, внутренний свет немного тише | Target не уменьшается; отпускание вне цели отменяет клик |
| Focus | Внешний focus ring | Подпись не сдвигается |
| Disabled | Disabled content + приглушённая поверхность | Нет нажатия, анимации glyph и haptic; причина рядом, когда она неочевидна |
| Busy | Статичный размер; индикатор 20 вместо glyph, label меняется при необходимости | Повторная команда не вызывается; label и доступное имя согласованы |
| Success | Обычно переход к результату или короткий status | Не превращать кнопку навсегда в зелёный баннер |
| Error | Исходная кнопка снова доступна, рядом текст ошибки | Не стирать ввод, повтор выполняет ту же операцию |

Текст label — button 16/22, weight520. Для очень короткой служебной кнопки допустим Label13/18; это не базовый размер CTA. При 200% масштабировании разрешить две строки и рост высоты, а не `maxLines=1` с многоточием. Обрезка «Сохранить…» в критической команде не допускается.

### 4.3. Защита от повторного действия

Busy выставляется при приёме команды, до suspend-вызова. Повторный tap в том же кадре проверяется на уровне state/controller. Нельзя полагаться только на визуальное disabled. При ошибке busy снимается в гарантированной ветке завершения. Для операций отправки/добавления в заметку сохраняется идентификатор capture: библиотека кнопок не является заменой защите от дублей в Core.

## 5. Icon button, tooltip и action menu

Круглая кнопка применяется к транспортным действиям; компактный r16 — к служебным действиям в строках и заголовке. В пределах одного toolbar форма согласована. Добавление проекта — PLUS в заголовке, без плавающего FAB.

Tooltip нужен для icon-only команд при мыши и клавиатуре: задержка hover500ms, появление opacity100ms, offset8dp, maxWidth240dp, padding8 × 10dp, Body Small14/20. Он содержит название команды, при наличии — комбинацию клавиш. Tooltip не является единственным доступным именем и не нужен над обычными подписанными кнопками.

Action menu: minWidth220, maxWidth320, r20, padding8; строка min48, padding12, glyph20, gap12. Временный scrim не обязателен для desktop popover; на compact используется sheet. Опасная команда идёт последней после разделителя. Focus переносится в меню, Escape закрывает его, возвращая фокус на исходную кнопку. Выбор команды закрывает меню и затем выполняет действие; экран не должен остаться под невидимым modal barrier.

## 6. Поля и единый редактор документа

### 6.1. KashaField

Поля для названия проекта, контекста проекта, даты, времени и настройки внешнего провайдера имеют внешний label. Placeholder — пример ожидаемого содержимого, не замена label. У одного поля не должно быть двух одинаковых строк с подписью сверху и внутри.

Порядок: label → 8dp → поле → 6dp → helper/error. Label13/18; value16/23; helper14/20. Необязательность обозначается текстом «(необязательно)» рядом с label, без красных звёздочек. Helper объясняет формат или последствия, а не повторяет имя.

| Состояние | Отображение |
|---|---|
| Empty | Placeholder в contrast-approved secondary; не 30%-ный почти невидимый текст |
| Filled | Text Primary; trailing clear только по смыслу |
| Focus | Контрастная граница и cursor Accent; stable height |
| Error | Текст под полем с конкретной причиной; error icon при необходимости |
| Disabled | Не получает ввод; причина рядом; значение читаемо настолько, насколько нужно принять решение |
| Read only | Нормальный контраст текста; если открывает редактор — явное действие «Редактировать» |
| Saving | Не блокировать набор текста; status относится к версии данных |
| Save failed | Несохранённое значение остаётся в редакторе; доступно «Повторить» |

Правка не вызывает ошибку на каждую промежуточную букву. Проверять формат после ухода из поля или попытки сохранить; после первой ошибки корректировать сообщение по мере исправления. Для даты/времени предусмотреть ввод с клавиатуры и picker как альтернативу. Не изменять текст пользователя молча ради форматирования, пока активна IME-композиция.

Clear имеет target48 и имя «Очистить …». Если поле содержит секрет провайдера, отсутствие визуального значения не должно трактоваться как отсутствие сохранённого секрета; показывается соответствующее текстовое состояние из privacy-документа. Не добавлять eye/copy без реальной команды.

### 6.2. KashaNoteText

Один `value` хранит весь документ. Первая непустая строка вычисляется как название для списков; это не второе поле и не отдельная модель ввода. Нельзя удалять первую строку из текста или добавлять её повторно при сохранении.

Полноэкранный редактор: фон Canvas либо одна спокойная Surface без визуального outlined-input, padding0–16 в зависимости от контейнера. В sheet допускается Surface r16 и padding16. Минимальная удобная область 180dp на телефоне, но на коротком экране после открытия клавиатуры высота определяется доступным viewport. Никакая цифра minHeight не должна выталкивать сохранение за экран.

Body17/25 для чтения длинного текста; основной UI Body16/23. Если первая строка визуально выделяется, она остаётся частью того же редактора, выделения и копирования; каретка не скачет между двумя контролами. До появления полноценной корректной rich-text реализации весь документ отображается единым Body Large — это лучше, чем два поля, притворяющихся одним.

Сохранять переносы строк, пустые строки внутри документа и unicode. Пустота определяется для доступности команд через `isBlank`, но хранение текста не должно обрезать все пробелы при каждом вводе. Нативные selection handles, меню копирования и работа IME допустимы и должны сохраняться.

Статусы «Сохраняем…», «Сохранено на устройстве», «Не удалось сохранить» находятся вне редактируемого текста. Их появление не сдвигает каретку и не прокручивает документ к началу. Не объявлять каждое автосохранение экранному диктору; ошибка объявляется один раз, смена экрана — по обычным правилам.

## 7. Переключатель, выбор и slider

### 7.1. KashaSwitchRow

Полная строка min64, label слева, switch справа; между ними 20dp. Визуальный track44 × 26, r13, thumb20, inset3. Это один toggleable semantics node, без двух параллельных кликов строки и thumb.

Выключен: Surface + functional outline, thumb Text Secondary. Включён: Accent track + On Accent thumb. Положение thumb и программное checked состояние обязательно; цвет не является единственным признаком. Disabled сохраняет выбранное значение.

Если переключение требует согласия на внешнюю обработку, tap открывает consent; switch не становится enabled до подтверждения и успешного применения. Ошибка сохранения возвращает предыдущую конфигурацию и показывает причину. Не создавать кратковременное ложное состояние «локально», если работа ещё идёт через внешнего провайдера.

### 7.2. Single-select list

Использовать для темы, языка, режима сортировки, AI-провайдера и повторов напоминания. Каждая строка min56, checked marker справа 24, title16/23, description14/20 ниже с gap4. Вся строка selectable, роль RadioButton, группа имеет имя. Выбранное значение обозначается check/контуром и доступным состоянием.

Не использовать десяток pills для списка настроек. Короткий выбор из двух реально равноправных состояний может быть общим segmented control: одна поверхность, min48, gap0, r16, внутренний selected area r12. Для «В заметки»/«В задачи» segmented control запрещён: это команды.

### 7.3. KashaSlider

Внешняя строка label + текущее значение; ниже track, зона ввода min48. Track3dp, thumb визуально 18–20dp с target48, functional outline при недостаточном контрасте. Левый и правый пределы читаются текстом, если без них смысл шкалы неясен. Значение озвучивается вместе с единицей: «Скорость, 1,5 раза», а не «0,5».

Slider применяется только к реально поддержанному параметру. Он не создаёт произвольные значения поверх дискретного Core: точки и шаг соответствуют диапазону модели. `onValueChange` меняет preview, `onValueChangeFinished` сохраняет значение; отмена взаимодействия восстанавливает последнее подтверждённое значение, если предварительный просмотр не был сохранён.

Arrow keys изменяют на один шаг; Home/End — к границам, если платформа их поддерживает. Screen reader использует increment/decrement. Не помещать 40dp Slider внутрь 40dp clipping-области: текущая высота в коде должна вырасти до доступного target.

## 8. Заголовок и навигация

### 8.1. Header

Заголовок раздела H1 30/35 либо H2 25/30 в плотном вложенном экране. Верхний gap до контента 16–24, справа максимум два постоянных действия. Back target48, title занимает остаток, more target48. Длинное название проекта в header переносится на две строки; в navigation breadcrumb допускается ellipsis с полным доступным именем.

Root-разделы имеют названия «Главная», «Проекты», «Задачи», «Настройки». На Home небольшой официальный знак может заменить повторяющийся текстовый заголовок, не создавая нового логотипа. Профиль из изображения не добавляется без соответствующей функции.

### 8.2. Bottom navigation

Одна поверхность Floating Surface r28, базовая видимая высота 72, горизонтальные внешние поля 16–20, нижний безопасный отступ учитывается снаружи. Внутри четыре равных сегмента: Главная/HOME, Проекты/FOLDER, Задачи/TASKS, Настройки/SETTINGS.

Glyph22, gap4, label12/16 weight500. Выбранный glyph и label — Text Primary, остальные — доступный Secondary. Локальное пятно около glyph: 44 × 32, r16, максимум Accent translucent; оно не заполняет всю вкладку отдельной pill. Состояние selected передаётся диктору, focus виден отдельно.

Tap переключает раздел с сохранением его контекста по сценарию. Повторное нажатие выбранной вкладки не останавливает запись и не создаёт новую. Навигация не вызывает haptic. При 200% текста высота растёт; labels можно переносить на две строки, либо применять адаптивную навигацию из документа платформ: при text scale>1.3 или измеренном overflow — раскладка 2 × 2 внутри той же единой поверхности, без отдельных pills. Уменьшать шрифт ниже 12 для умещения запрещено.

### 8.3. Global player как компонент

Surface High, r24, min80, padding12. Располагается непосредственно над nav, gap8. Семантика — именованная группа «Запись»/«Проигрыватель», не техническое `global-player`. У waveform нет отдельного focus stop, если она декоративна; seek создаёт один adjustable node.

Transport target48; мини-waveform получает оставшуюся ширину; elapsed/duration — табличные цифры, Label13/18. Заголовок аудио максимум одна строка при обычном масштабе и две при крупном. При нехватке ширины времена уходят в следующую строку, но Pause и Stop остаются доступными. Параллельные запись и playback запрещены доменным сценарием, а не конкурирующими кнопками внутри панели.

Не дублировать активные transport controls на Home без необходимости. На полном recording view видимые действия принадлежат одному presenter; Global Player сворачивает дублирующую строку либо используется как её нижняя панель по [04](./04-capture-player.md). Переключение представления не создаёт второй recorder/controller.

## 9. Строки проектов, заметок, задач и аудио

### 9.1. Общий row contract

Строка — одна читаемая горизонтальная композиция, без карточки внутри карточки. Нажатие вызывает основное открытие. У независимой дополнительной команды отдельный target и отдельное accessible name; клик по ней не всплывает в открытие строки. Стабильный `key=id` обязателен для фокуса и reorder.

Hover: поверхность на один локальный шаг светлее. Pressed: luminance shift, scale не больше 0.99 для длинной строки. Selected — контрастный marker плюс спокойная Surface Highest; нельзя снижать общую alpha строки до 0.72 при drag, делая текст плохо читаемым.

| Строка | Структура | Обрезка / вторичные элементы |
|---|---|---|
| Project | Glyph22 → title → optional description; pin state; disclosure | Title1–2 строки, description1–2; без счётчиков ради заполнения |
| Note | Первая непустая строка → preview → modified date + audio marker | Title2 строки максимум; preview1–3; полный текст при открытии |
| Task | Completion target48 → text → due/reminder | Text2–3 строки в списке; срок и marker только при наличии |
| Audio source | Play target48 → источник/дата + duration; optional waveform | Имя 2 строки; waveform не обязательна в каждом источнике, если перегружает список |
| Setting | Label → current value/description; disclosure/switch | Значение не переносится в нечитаемые микроподписи |

Note preview исключает уже показанную строку title, чтобы не повторять один текст дважды. Метаданные — Body Small14/20 либо Label13/18, доступный Secondary; Text Tertiary только если контраст подтверждён на соответствующей поверхности. Audio marker имеет доступное описание «Есть аудиозапись» через semantics строки; отдельная немая микрокнопка 16 × 16 запрещена.

Pin в строке может быть только индикатором, а изменение — в more menu. Если pin интерактивен, target48 обязателен, имя «Закрепить проект …»/«Открепить …». Pinned projects сохраняют имя и обычный FOLDER: не обязательно заменять их предметный glyph на большую булавку.

### 9.2. Completion control

Визуальная фигура 24 × 24, target48. Incomplete: скруглённый собственный контур с r7, stroke1.8–1.9; checked: залитая фигура и check. Использовать единый glyph/state geometry, не стандартный Material Checkbox и не два несвязанных рисунка.

Вся текстовая часть строки открывает задачу; completion target только выполняет. Role Checkbox, label «Выполнить задачу: …», checked передаётся отдельно. Pressed scale0.94 только визуальной фигуры. После подтверждения Core контур morph/fill220–320ms, text слегка приглушается, затем строка уходит в Архив. Время удержания перед удалением из списка 300ms; итог от подтверждения до ухода ориентировочно 550ms. В Reduce Motion — статичная галочка и короткое opacity, без движения соседних строк.

Во время запроса target не принимает второй tap. При ошибке строка остаётся, checked возвращается в исходное значение, показывается «Не удалось выполнить задачу. Повторите». Не обещать Undo, если восстановление из Архива отсутствует в текущем доменном контракте; компонент snackbar поддерживает action только при наличии реальной обратной команды.

После удаления строки фокус переходит к следующей задаче на том же месте, затем к предыдущей, а при пустом списке — к заголовку/empty-state. Screen reader получает одно сообщение «Задача выполнена и перемещена в архив», без озвучивания каждого кадра morph.

## 10. Сортировка и перестановка

### 10.1. Sort control

Один quiet control: SORT20 + «По дате изменения» + DOWN16, target min48, left alignment. При длинной локализации он растёт по высоте. Открывает sheet на телефоне, anchored popover на wide. Заголовок «Сортировка», четыре single-select строки: «По алфавиту», «По дате создания», «По дате изменения», «Вручную».

Текущий режим виден до открытия, выбранная строка отмечена check. Переключение сохраняет preference в существующую модель и закрывает selector. Ошибка сохранения не выдаётся за успех: либо применяется подтверждённый режим, либо возвращается предыдущий с сообщением. Отдельная кнопка «Применить» для этого короткого списка не нужна.

### 10.2. Manual reorder

Reorder включается только в MANUAL. В прочих режимах long press не меняет порядок и не переключает режим молча. Вход в MANUAL показывает одну короткую подсказку «Зажмите элемент и переместите»; это не постоянный баннер.

Последовательность:

1. Long press500ms с учётом системной настройки жеста; движение до порога допускается в пределах touch slop платформы.
2. Поднятый item получает z-index, scale1.015, Surface Highest и мягкую локальную тень. Его исходная позиция сохраняется placeholder той же высоты.
3. Появляется DRAG glyph, haptic lift. Фигура движется вместе с указателем без накапливающегося отставания.
4. Смена позиции — когда центр поднятого item пересёк середину соседнего; haptic selection с ограничением частоты.
5. У верхнего/нижнего края доступного списка зона автоскролла 48dp; скорость 0→360dp/с по глубине входа. Safe area/player/nav не считаются зоной drop.
6. Drop фиксирует порядок один раз, возвращает scale1 и убирает placeholder. Соседи занимают окончательное место через spring.
7. Cancel/Escape/потеря pointer возвращают авторитетный порядок до жеста. Не сохранять промежуточный массив как финальный.

Смена обычной сортировки не перезаписывает manual-order. Возврат в MANUAL восстанавливает ранее заданный порядок. Закреплённая и незакреплённая группы имеют отдельную политику; перетаскивание через границу не меняет pin автоматически. Для скрытых фильтром элементов нельзя сохранять неполный массив как полный порядок без доменного merge-контракта.

Доступная альтернатива: custom actions «Переместить выше» и «Переместить ниже» у строки; на desktop те же команды в more menu. После перемещения озвучивать «Позиция 3 из 8». Не требовать точного long press от screen reader пользователя. При незавершённом save порядок и ошибка остаются понятными; повторная перестановка не должна обгонять предыдущую запись в хранилище.

## 11. Bottom sheet и диалог

### 11.1. Sheet

Одна Floating Surface с верхними r28. Scrim из `overlay.scrim`: dark `rgba(10,8,7,0.56)`, light `rgba(33,26,21,0.32)`; фон не размывается на весь viewport. Handle32 × 4, отступ сверху 10, до заголовка 16. Handle декоративный, не единственный способ закрытия. Заголовок H3 21/27, справа Close target48.

Горизонтальные поля 20; maxWidth560 на больших экранах. Короткий выбор занимает естественную высоту, ограниченную 85% доступной высоты. При клавиатуре форма занимает доступное пространство и прокручивается; нижние действия видны над IME. Контент и footer не имеют независимых конкурирующих vertical scroll.

Сценарии: выбор сортировки, проекта, существующей заметки, срока и частоты напоминания. Большая форма или длинный документ может перейти на отдельную page с тем же содержимым. Не открывать sheet поверх sheet для каждого уровня: выбор проекта → заметки меняет внутренний шаг одного контейнера с Back.

Dismiss по scrim/swipe/Back разрешён для незаполненного выбора. Если есть несохранённый пользовательский текст, закрытие сохраняет локальный ввод по сценарию или открывает подтверждение потери; не стирает его молча. Выполняющийся commit нельзя прервать жестом без явной команды отмены на уровне controller.

Focus заперт внутри modal, начальный focus на заголовке/первом осмысленном элементе, а не автоматически на поле с вызовом клавиатуры. При закрытии возвращается на opener, если он ещё существует. Название sheet доступно screen reader.

### 11.2. Confirmation dialog

Width calc: viewport−48, max440, r24, padding24. Title21/27, body16/23, gap12, до actions24. Кнопки горизонтально только если подписи помещаются при текущем размере текста; иначе вертикально, primary/destructive и безопасная отмена имеют полноразмерные targets.

Текст называет объект и последствие: «Удалить эту запись?» → «Аудио и несохранённый текст будут удалены». Если реальная доменная операция имеет другие последствия, использовать её точную формулировку из сценария. Не писать абстрактное «Вы уверены?» без объекта.

Безопасная отмена — default focus. Enter не должен случайно подтверждать destructive сразу после открытия с клавиатуры. Escape закрывает без удаления. Подтверждение вызывает одну команду и состояние busy; ошибка оставляет объект доступным. Haptic confirmation возможен только при принятой команде и не заменяет текст.

## 12. Статусы, ошибки и загрузка

### 12.1. Inline status

Icon20 + текст 14/20, gap8. Использовать нейтральную Surface только когда статус действительно требует отделения. Успех/ошибка всегда имеют текст, а не только зелёный/красный кружок.

Длительный процесс имеет точное имя этапа: «Расшифровываем», «Приводим в порядок», «Готовим текст». Не отображать «ИИ думает», звёздочку или фальшивый процент. Если неизвестно время окончания, progress indeterminate. При известном объёме progress показывает измеренную долю и не замедляется искусственно ради анимации.

### 12.2. Snackbar / toast

Floating Surface r18, min56, padding12–16, gap12, message14/20, action min48. Расположение над player/nav либо над клавиатурой; не закрывает Pause/Stop/Save. На desktop maxWidth480.

Короткий успех без действия: видимость 4s. Сообщение с полезным действием: минимум 8s и продление на hover/focus; системные настройки доступности могут увеличить время. Ошибка сохранения или потеря доступа к микрофону не должны исчезать только по таймеру: постоянный inline state остаётся до разрешения.

В очереди не повторять десять одинаковых ошибок от polling. Группировать по коду и объекту; новая критическая ошибка заменяет менее важный успех. Screen reader live region polite; assertive только для действительно немедленной остановки/потери записи. Не произносить technical code.

### 12.3. Empty / error / loading block

| Ситуация | Содержимое |
|---|---|
| Пустой список | Короткий title, одно объяснение, одно реальное следующее действие |
| Ничего не найдено | Поисковый запрос, возможность очистить; без намёка на потерю данных |
| Ошибка загрузки | Что не удалось открыть, «Повторить», ранее загруженное содержимое по возможности сохраняется |
| Ошибка сохранения | Введённый текст/выбор на месте, заметный статус и повтор |
| Не поддерживается на платформе | Точная недоступная возможность и доступная альтернатива; не пустой disabled control без причины |
| Loading | Нейтральный индикатор и этап; существующий контент не заменяется skeleton при каждом refresh |

Иллюстрация empty-state может использовать официальный знак или предметный glyph в одном тоне, но не создаёт дополнительную декоративную сцену. Skeleton разрешён для реальной первой загрузки списка; shimmer отключён по умолчанию, чтобы не превращать интерфейс в мерцающую панель.

## 13. Единый реестр иконок

### 13.1. Правило источника

Целевой контракт геометрии и motion передан в [registry.json](./icons/registry.json); SVG и [анимированный атлас](./icons/atlas.html) генерируются из этого реестра. Это комплект передачи для переноса в существующий `KashaIcons.kt`, используемый всеми Compose-платформами. Текущий runtime в рамках документационной поставки не заменён. После переноса один реестр остаётся авторитетным, Kotlin/SVG/атлас — его производными; вручную редактируемую вторую коллекцию не заводить.

Каноническая сетка 24 × 24, safe box2…22, nominal stroke1.8; текущий 1.9 допустим при миграции до общей оптической сверки. Round cap/join. Визуальный размер 20–24; stroke масштабируется вместе с glyph. Большие иконки не рисуются с постоянным stroke1.8 physical px.

Сначала централизовать геометрию как команды path/line/ellipse/roundRect и выбрать один rasterizer; затем экспорт SVG с `viewBox="0 0 24 24"`, `currentColor`, явными stroke-linecap/join. Runtime не загружает внешний icon pack. Официальный логотип хранится отдельно и не становится `Glyph.K`.

Не рисовать дополнительные декоративные значки для заполнения каталога.

Каждый новый glyph при интеграции проверяется в20/22/24/32dp, dark/light, normal/selected/disabled. Приложенные статические проверки атласа относятся к20/24/32dp; это не утверждение о выполненной проверке22dp в runtime. Вес линии и оптическая плотность должны совпадать; иконка не узнаётся только по движению. Значок gear не становится «солнцем» из-за чрезмерной редукции; связанная с текстом роль определяется label.

## 14. Компонентная приёмка

Для каждого компонента в общей демонстрационной поверхности показать dark/light, 100%/200% текста, narrow320dp и wide, default/hover/pressed/focus/disabled/busy/error по применимости. Предпросмотр — внутренний инструмент разработки, не дополнительный продуктовый экран.

Обязательные проверки:

- Кнопки не меняют ширину при busy; повторный tap не вызывает вторую команду.
- Нельзя потерять фокус под sheet; Escape и Back возвращают к исходному элементу.
- Checkbox, switch, slider и selected tabs различимы без цвета и озвучиваются корректно.
- Ни одна critical action не обрезана при 200%; target не меньше 44 × 44.
- Ошибка сохранения оставляет введённый текст и даёт повтор; snackbar не перекрывает transport.
- Смена сортировки туда и обратно восстанавливает ручной порядок; cancel drag его не записывает.
- В приложении нет второго icon pack, видимого MAGIC, двух полей заголовок/текст и четырёх отдельных navigation pills.
- Реальные системные разрешения используют системный диалог; Kasha-оболочка не подделывает его.
