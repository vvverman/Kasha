# Адаптивность, доступность и взаимодействие на платформах

Статус: целевые требования к общему Kasha UI и тонким платформенным адаптерам. База аудита — `main` `ca3793e4e603dcf340cdaca565f089bd57c5d77a`, параллельная iOS-ветка PR [#9](https://github.com/vvverman/Kasha/pull/9) в снимке `d22d1dfb3cd9baa801afa4249e48988107998a36`. Матрицы ниже задают приёмку, а не заявляют, что проверка на устройствах уже проведена.

Связанные документы: [основы и tokens](./02-foundations.md), [компоненты](./03-components.md), [запись и плеер](./04-capture-player.md), [проекты, заметки, задачи](./05-projects-notes-tasks.md), [настройки и приватность](./06-settings-privacy.md), [motion](./08-graphics-motion.md).

## 1. Текущее ограничение реализации

[StudioApp.kt](../../composeApp/src/commonMain/kotlin/brain/studio/StudioApp.kt) ограничивает всё приложение шириной 430 dp, с полями 20 dp, одним центральным столбцом и четырьмя отдельными item-поверхностями снизу. В [web index](../../composeApp/src/wasmJsMain/resources/index.html) дополнительно зафиксированы `max-width:430px` и `overflow:hidden`. Это текущая оболочка, а не конечная desktop-адаптация.

В [KashaNavigation.kt](../../composeApp/src/commonMain/kotlin/brain/studio/ui/KashaNavigation.kt) уже есть selected/Role.Tab и focus/hover/pressed состояния; в [KashaUi.kt](../../composeApp/src/commonMain/kotlin/brain/studio/ui/KashaUi.kt) и [KashaNoteText.kt](../../composeApp/src/commonMain/kotlin/brain/studio/ui/KashaNoteText.kt) используются отдельные semantic labels. Это полезная база, но одни `contentDescription` не подтверждают правильную структуру screen reader. `global-player` сейчас техническая подпись, её нужно заменить продуктовой семантикой и доступными дочерними действиями.

Верхние/нижние системные insets, клавиатура, 200% текста, desktop-разделение и доступная альтернатива drag требуют отдельной реализации и проверки. iOS production PR меняет аудио, хранилище и уведомления; сам по себе он не устраняет эти ограничения shared UI.

## 2. Базовые правила измерений

Размеры UI задаются в логических единицах `dp`, текст — в `sp`. Для web проверка viewport/zoom использует CSS-пиксели. Физические пиксели экрана не подставляются вместо `dp`: ширина iPhone в пикселях рендера не определяет breakpoint. Толщина glyph масштабируется с density, графика не растягивается bitmap-увеличением.

`W` — доступная ширина окна после левого/правого системного inset. `H` — высота после верхнего/нижнего безопасного inset и системных перекрытий. Размеры навигации, player, клавиатуры и локального toolbar вычитаются отдельно при расчёте доступного контента. Нельзя вычесть один safe area дважды: корневой layout отвечает за внешние insets, дочерний — только за собственные панели.

Breakpoints определяются текущим окном, а не названием устройства. iPad в узком Split View использует мобильную композицию; macOS при узком окне — тот же fallback. Пересечение breakpoint меняет размещение уже существующих объектов, но не создаёт новую запись, repository, model или navigation stack.

### 2.1. Сетка

| Доступная ширина W | Режим | Горизонтальные поля | Структура |
|---|---|---|---|
| 320–359 dp | Компактный мобильный | 16 dp | Один столбец, полная ширина контента; действия чаще вертикальные |
| 360–599 dp | Мобильный | 20 dp | Один столбец; между 431–599 ширина чтения ограничивается 480 dp и центрируется |
| 600–1023 dp | Планшет/среднее окно | 24 dp | Контент до 720 dp, длинный текст до 640 dp; нижняя навигация до 560 dp |
| 1024–1199 dp | Desktop | 32 dp | Sidebar 224 dp + 24 dp промежуток + одна основная область |
| ≥1200 dp | Широкий desktop | 32 dp, общая оболочка до 1440 dp | Sidebar 224 dp; в проектах возможны список заметок 320 dp + 24 dp + текст минимум 420 dp; настройки/Главная остаются одной рабочей областью |

В 320 dp рабочая ширина равна 288 dp. В 390 dp — 350 dp. В 430 dp — 390 dp. Эти значения — контрольные примеры для макета. При ширине меньше 320 dp приложение сохраняет доступ к данным и действиям вертикальным reflow, хотя художественная композиция не является эталоном приёмки. Горизонтального скролла приложения для повседневных действий нет.

Максимальная ширина desktop не должна оставлять телефонную рамку посередине пустого окна. Центрируется общая рабочая композиция с navigation/context/content; весь фон заполняет окно темой Kasha. Имитации рамки телефона, камеры, Dynamic Island и времени 9:41 в рабочем приложении нет.

### 2.2. Вертикальный ритм

Общий шаг 4 dp. Основные интервалы: 8 dp между связанными действиями, 12 dp между glyph/текстом, 16 dp внутри поверхностей, 24 dp между содержательными блоками, 32 dp между крупными зонами. На узком/коротком экране сначала сокращаются свободные интервалы 32→24→16 dp, затем уменьшается декоративный объект. Размер текста и target не уменьшаются ради сохранения воздуха.

Для обычного списка отступ последней строки до перекрывающей панели не меньше 16 dp. Если panel наложен поверх списка, `contentPadding.bottom` равен фактической высоте панели + отступам; магическое постоянное число 120 dp не работает при увеличенном тексте.

## 3. Главная на разных размерах

### 3.1. Нормальная высота

Композиция «верхний бренд/статус — capture object — управление — навигация» соответствует [04](./04-capture-player.md). Базовый orb 184 dp idle, 196 dp recording, резервирующий контейнер 224 dp; waveform высотой до 96 dp по реальному сигналу. Увеличение orb не сдвигает кнопки и таймер.

При доступной высоте контентной области от 620 dp можно использовать полный световой объект и крупный заголовок. На планшете orb не увеличивается пропорционально всему экрану: максимум декоративного контейнера 280 dp, функциональная кнопка и touch target остаются предсказуемыми. Пустота вокруг является частью композиции, но от неё нельзя зависеть для доступа к действиям.

Таймер выравнивается по центру, использует tabular figures и зарезервированную высоту. Формат после часа расширяется до `1:00:24` без уменьшения размеров цифр. Для screen reader таймер — понятное время, а не строка отдельных символов.

### 3.2. Короткое окно и landscape

`Hcapture` — высота, оставшаяся Главной после safe areas, header и нижних панелей.

| Hcapture | Адаптация |
|---|---|
| ≥620 dp | Полная orb-композиция, штатные крупные статусы |
| 460–619 dp | Верхний декоративный отступ 16 dp, orb-контейнер 200 dp; заголовок не более Display 38/42 при 100% font |
| 320–459 dp | Декоративный orb выключен; функциональная waveform 64–80 dp, таймер и три действия в вертикальном потоке |
| <320 dp или открыта большая клавиатура | Убирается вся декоративная графика; прокручиваемый статус/редактор, постоянно достижимые Pause/Resume и Завершить |

При 200% font решение принимается по фактическому занимаемому месту; даже высокое устройство может использовать компактный вариант. Сокращение orb не заменяет запись generic spinner и не превращает paused waveform в плоскую линию.

На landscape-телефоне не делить Result на два узких текстовых столбца. Сохранять один поток, статусы и действия; боковой orb допустим только когда остаётся минимум 320 dp для основного блока и его присутствие не мешает клавиатуре. При конфликте orb исчезает.

### 3.3. Result

Текст результата использует всю доступную ширину до предела чтения 640 dp. Минимум 16/23 при 100% масштабе, масштабирование без fixed-height clipping. «Привести в порядок» и две отдельные команды «В заметки» / «В задачи» перестраиваются по месту: кнопки рядом только если каждая целиком вмещает label и внутренние поля 16 dp; иначе вертикально.

Нет отдельного title-поля ни на desktop, ни в compact. Первая непустая строка остаётся частью документа. Редактор открывается в том же состоянии текста, выделения и прокрутки после смены ориентации, темы, языка и размера окна.

## 4. Нижняя навигация и Global Player

### 4.1. Навигация

При обычном масштабе нижняя навигация — **одна** поверхность радиусом 24–30 dp, визуальная высота 72 dp, четыре равных элемента: Главная, Проекты, Задачи, Настройки. Leading icon 22–24 dp, label Navigation 12/16. Минимальная область пункта 48×48 dp. Активное состояние — яркость glyph/label и слабый локальный свет, без отдельной большой цветной pill.

Длинные переводы и увеличение текста нельзя решать `maxLines=1` с многоточием на всех названиях. Адаптивный fallback:

- При font scale ≤1,3 и достаточной измеренной ширине — четыре пункта в ряд.
- При font scale >1,3 **или** переполнении хотя бы одного полного label — сетка 2×2 в одной общей поверхности.
- В 2×2 glyph стоит слева от label с промежутком 8 dp; высота ряда минимум 56 dp, при 200% — по содержимому, ориентир 64–80 dp. Между ячейками 4 dp; поля общей поверхности 8 dp.
- Четыре названия и selected semantics сохраняются. Это reflow одного навигационного компонента, а не четыре отдельные карточки.

Высота навигации — результат layout; контент получает её фактический размер. Поверхность располагается выше нижней safe area с интервалом 8 dp; системный home indicator не лежит на подписи. При широком планшете nav центрируется и не растягивает элементы на всю ширину.

### 4.2. Sidebar desktop

При W ≥1024 dp четыре пункта переходят в один левый navigation region шириной 224 dp. Верхний фирменный знак небольшой; под ним 24 dp и список разделов. Строки навигации минимум 52 dp, glyph 22 dp, label 16/23. Внизу свободное пространство; не добавлять профиль, workspace selector, аккаунт или dashboard ради заполнения.

Sidebar не дублирует одновременно нижнюю навигацию. Выбранный раздел одинаков в модели состояния. При resize ниже breakpoint sidebar превращается в нижнюю поверхность и focus остаётся на соответствующем пункте или выбранной странице, без перезапуска экрана.

### 4.3. Global Player

Базовая высота панели минимум 80 dp, обычно 80–96 dp; при крупных шрифтах растёт по содержимому. Поля 12–16 dp. Player отделён от navigation 8 dp. В обычном мобильном режиме он стоит непосредственно перед навигацией; на desktop закреплён у нижнего края основной рабочей области, не внизу длинной страницы за пределами окна.

Команды транспорта имеют target 48×48 dp. Компоновка recording: Pause/Resume, мини-waveform, elapsed, Завершить. При 320 dp и 200%: первая строка — статус/время, вторая — две команды, waveform между строками только если не вытесняет их. Playback: заголовок отдельной строкой, затем progress/time и transport. Минимальная 80 dp не является максимальной.

У full recording view и compact player единый источник состояния и одна сессия. Если полный контрол записи уже виден на Главной, дублировать второй одинаковый набор кнопок в плеере не нужно; при уходе с Главной transport остаётся в Global Player. Навигация никогда не становится кнопкой записи.

При открытой экранной клавиатуре скрывается только неактивная навигационная/декоративная часть, которая мешает редактированию; активная запись остаётся видимой в компактной панели над клавиатурой. В ней обязательны Pause/Resume, elapsed и Завершить. Высота минимум 64 dp при обычном font, при 200% — две строки по содержимому. Кнопка перехода к записи имеет label «Открыть запись».

Модальное подтверждение временно имеет приоритет focus, поэтому background player недоступен под модальным слоем. Если запись продолжается во время диалога, её реальное состояние явно названо в диалоге; диалог короткий и имеет понятный выход. Закрытие любого sheet само по себе не завершает аудио.

## 5. Проекты, заметки и задачи

### 5.1. Списки

При W <1200 dp используется последовательная навигация: Проекты → список заметок → заметка. Header, sort control и pinned section занимают только необходимую высоту; списки прокручиваются независимо от общей навигации. Sort имеет полный видимый текущий режим.

В строках названия можно обрезать после двух строк для компактного просмотра, preview заметки — после трёх. При 200% число строк не ограничивается так, чтобы строка стала безымянной; допустимо показать меньше preview, сохраняя title и действия. Полный текст доступен в открытой сущности и accessible name. Точный срок задачи не должен быть виден только после hover.

Нет фиксированной высоты всех строк 64 dp: minimum задаёт нижнюю границу, текст определяет рост. Разделитель начинается под текстовой колонкой после leading glyph, а не под completion control. Даты и аудиометка переносятся во вторую/третью строку до пересечения с more/disclosure.

### 5.2. Два столбца на широком desktop

При W ≥1200 dp список заметок выбранного проекта может занимать contextual pane 320 dp, справа — заметка минимум 420 dp, максимум ширины чтения 640 dp. Список проектов не добавляется третьим постоянным столбцом: пользователь выбирает проект и получает его заметки; путь в header возвращает к проектам.

Открытая заметка сохраняет локальный draft, selection и scroll при переходе между одним и двумя столбцами. Browser Back/system Back закрывает detail либо возвращает предыдущий уровень по одному шагу, а не сразу сбрасывает весь раздел. Split layout не создаёт второй экземпляр одной заметки с независимым autosave.

Главная не становится dashboard на desktop. Настройки ограничены шириной 720 dp; длинный редактор подключения — 640 dp. В пустой правой области проекта можно показать «Выберите заметку», без маркетингового orb, фотографий и бесполезных метрик.

### 5.3. Task Editor

При доступной высоте ≥640 dp и масштабе текста ≤1,3 — bottom sheet с верхним радиусом 28 dp и высотой по содержимому до 90% safe height. На коротком окне, при 200% или открытой клавиатуре, не помещающей форму, — полноценная страница. Переход сохраняет введённый текст/срок/напоминание.

Header и действие закрытия доступны; основная форма прокручивается одним контейнером. Дата и время стоят рядом только когда оба значения и controls целиком помещаются с target 48 dp; иначе вертикально. Системные date/time pickers допустимы. Их внешний вид не заменяется самодельными wheels только ради отличия от iOS/Material.

Повтор напоминания имеет текстовое название и selected-state, а не только цвет. Ошибка разрешения уведомлений располагается рядом с напоминанием и не мешает сохранению текста задачи.

## 6. Клавиатура, insets, окна и системные панели

### 6.1. Экранная клавиатура

Открытие IME поднимает видимую область редактирования, а не перекрывает последнюю строку. Focused field/caret прокручивается минимум на 12 dp выше клавиатуры или прикреплённого toolbar. Использовать реальные динамические insets; высота клавиатуры не фиксируется как 300 dp.

Редактор длинного текста получает внутреннее `bringIntoView` при перемещении caret. Пользователь может просмотреть начало/конец текста, выбрать слово и нажать действие над клавиатурой без случайного drag списка. Прокрутка не переключает focus и не скрывает клавиатуру автоматически.

На коротком окне Save/actions идут в обычном потоке либо компактной sticky-панели, сохраняющей минимум две видимые строки редактируемого текста. Если sticky-панель заняла бы почти весь экран, её делают прокручиваемой частью формы, а не уменьшают шрифт/targets. Внешний API-ключ и длинный URL не растягивают окно: поле прокручивает содержимое по собственному правилу, остальная форма не двигается горизонтально.

### 6.2. Safe area

Главный фон и декоративный свет могут рисоваться под системными областями. Текст, кнопки, навигация и gesture handles — внутри safe area. На тёмной теме системные индикаторы светлые, на светлой — тёмные, если это контролируется платформой. Статус записи не рисуется вместо системного indicator микрофона.

Проверить устройства с вырезом, без выреза, Android gesture navigation и трёхкнопочной навигацией, iPad Split View, desktop titlebar. Не использовать условие «если iPhone, padding 44». Insets — данные ОС, не модель телефона.

### 6.3. Изменение окна и жизненный цикл

Поворот, resize, split view и внешняя клавиатура не являются причиной перезапуска записи, потери результата, закрытия consent либо двойного сохранения. Recomposition восстанавливает focus по устойчивому ID. При переключении desktop dual-pane в mobile detail сохраняется выбранная заметка; Back остаётся доступен.

Background/foreground поведение определяется аудиоадаптером. Если ОС действительно прервала запись, UI показывает прерывание и проверенную возможность восстановления, а не продолжает анимировать waveform как будто запись идёт. Наличие окна в foreground не доказывает работу микрофона. При возвращении перечитать разрешения и telemetry до сообщения «Идёт запись».

## 7. Масштаб текста 200%

Kasha принимает системное масштабирование текста вплоть до 200% минимум без обрезки обязательных действий. Шрифт Geologica остаётся настоящим текстом. Display/Hero могут перейти на менее крупную ступень композиции на тесном viewport, но пользовательский text scale не отключается и итоговые читаемые размеры не уменьшаются ниже соответствующей доступной шкалы.

Для web независимая проверка: изменение размера текста до 200% не приводит к потере функций; reflow при эффективной ширине 320 CSS px не требует двухмерной прокрутки обычного контента. Эти проверки решают разные задачи: увеличение font не заменяет проверку browser zoom. Основание — [W3C Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) и [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).

| Компонент | При 100% | При 200% |
|---|---|---|
| Header H1 | 30/35, одна/две строки | Перенос без наложения Back/More; кнопки отдельным краем либо строкой |
| Body | 16/23 | Масштабируется; поля и строки растут |
| Label 13/18 | Над полем | Полностью виден, не превращается в placeholder |
| Primary 56 dp | Минимум 56 dp | `heightIn(min=56)`, растёт от текста + 16 dp верх/низ; label максимум две строки для команд |
| Row 76 dp | Минимум 76 dp | Основной текст + metadata в несколько строк, trailing action не перекрывает текст |
| Navigation | Четыре в ряд | 2×2 одна поверхность |
| Recording actions | Три зоны | Pause/Resume первым большим действием; cancel/finish переносятся в следующую строку при нехватке места |
| Consent | Крупный sheet/page | Полная страница, вертикальные кнопки, всё читается прокруткой |
| Player | 80–96 dp | Отдельные строки title/status, progress, transport |
| Date/time | Возможно в ряд | Обычно вертикально |

Приложение не вводит собственный уменьшитель текста, компенсирующий настройку ОС. Мелкий декоративный текст не превращается в необходимую инструкцию. Ни один продуктовый текст при 100% не меньше 11 sp; на 200% он увеличивается соответственно.

Для web-разметки с поддержкой переопределения текстовых стилей дополнительно проверить одновременно: межстрочный интервал 1,5 размера шрифта, отступ после абзаца 2 размера, межбуквенный 0,12 размера, межсловный 0,16 размера. Эти значения не заменяют фирменную шкалу по умолчанию: интерфейс должен выдерживать пользовательскую настройку без потери содержимого и действий. Применимость к выбранному renderer фиксируется отдельно; canvas не используется для намеренного обхода доступности текста. Основание — [W3C Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html).

## 8. Контраст и значение цвета

Целевой стандарт интерфейса — WCAG 2.2 AA, с отдельными более строгими правилами Kasha. Для обычного текста WCAG требует 4,5:1, для крупного допускает 3:1; Kasha использует **4,5:1 для всех смысловых UI-текстов**, включая крупные статусы, labels, placeholder, metadata и helper. Это снижает риск ошибки классификации variable-weight текста. См. [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Значимые границы/состояния controls и информационная графика имеют не меньше 3:1 к прилегающему фону, если именно они позволяют распознать элемент/состояние. Малоконтрастный hairline допустим как разделитель уже понятных блоков, но не как единственное изображение незаполненного checkbox, focus или границы поля. См. [W3C Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

### 8.1. Обязательные semantic aliases

Реестр цветов и расчётов — [design-tokens.json](./tokens/design-tokens.json). Компоненты используют semantic tokens, не вставляют исходные hex как будто все пары проходят AA.

| Применение | Тёмная тема | Светлая тема | Причина |
|---|---|---|---|
| `text.tertiary` / осмысленный muted | `#ACA095` | `#70665D` | Исходные muted пользователя не проходят 4,5 на всех surfaces |
| `border.control` | `#91877D` | `#81776D` | Контур интерактивного поля/completion control должен читаться |
| `focus.ring` | `#E8C79F` | `#7A583B` | Явное выделение focus в обеих темах |
| `accent.content` на светлой теме | По теме/tokens | `#7A583B` | Исходный `#886445` на `#EEEAE0` даёт около 4,419:1, недостаточно для текста |
| `status.error.content` | `#D08E86` | `#974C45` | Ошибка читается как текст; исходный error остаётся цветовой основой |
| `status.success.content` светлый | По теме/tokens | `#4E6547` | Семантический текст без светлого «светофора» |
| `status.warning.content` светлый | По теме/tokens | `#745629` | Читаемое предупреждение |

Контрольные значения: тёмный исходный `#91877D` на Surface `#27231F` ≈4,431:1; светлый исходный `#938A81` на Canvas `#F7F5EE` ≈3,108:1. Это не допустимые secondary labels. `text.decorativeMuted` хранит исходный визуальный тон только для декора, который не несёт необходимого смысла. Конкретные значения округлены здесь для пояснения; приёмка считает исходные float ratios без округления вверх.

Фактический фон включает radial light, blur, grain, полупрозрачную поверхность и hover. Проверять худшую пару под текстом после композиции слоёв, а не только base hex. Если spot уменьшил контраст, под текст добавляется спокойная непрозрачная surface либо меняется semantic content; нельзя увеличивать чёрную тень текста ради прохождения.

### 8.2. Состояния помимо цвета

| Состояние | Дополнительный сигнал |
|---|---|
| Recording | Текст «Идёт запись», таймер, Pause и Завершить |

## 9. Screen reader и семантика

### 9.1. Структура страницы

Каждая страница имеет понятное название и один главный heading. Screen reader получает порядок: heading → важный текущий статус → основной контент → локальные действия → Global Player → navigation. На desktop navigation region доступен в естественном порядке и через средства обхода областей; переход в контент не требует проходить длинный список каждый раз.

Glyph внутри уже подписанной кнопки декоративен: его `contentDescription=null` либо эквивалент, иначе получается «Пауза, pause icon, кнопка». Самостоятельная icon button всегда получает русское действие. Логотип без действия — «Kasha», один раз на значимой заставке/брендовой области; декоративный watermark, grain, shadow, bloom и орбиты исключаются из accessibility tree.

Не объединять всё содержимое Global Player в один `contentDescription`: это уничтожает отдельный доступ к Pause/Stop/Seek. Группа имеет название, дочерние controls — свои роли и labels. Likewise row с отдельным completion и Edit не является одной кнопкой с несколькими скрытыми обработчиками.

### 9.2. Контракт элементов

| Элемент | Семантическая роль | Accessible name/value/state |

| Recording Pause | Button | «Поставить запись на паузу» |

Visible label входит в accessible name. Например, «В задачи» нельзя озвучивать как «Экспортировать объект». Полное имя длинной заметки доступно screen reader, но тело документа не зачитывается как label каждой кнопки.

### 9.3. Объявления и живые значения

Начало записи, пауза, возобновление, завершение и итоговое сохранение объявляются один раз. Таймер обновляется визуально каждую секунду, но не становится ежесекундным assertive announcement. Пока focus на timer, доступно актуальное value; по явному фокусу зачитывается текущая длительность. Смену фазы обработки озвучивать polite, не перехватывая чтение текста.

Процент загрузки модели объявлять только крупными шагами (например, каждые 10%) и при завершении; не прерывать чтение формы. Ошибка поля озвучивается один раз при валидации, затем доступна по связи field-error. Формулировка «Сохранено» доступна как status, но focus не перемещается на toast.

Автопереход autoRoute после READY сообщает «Выбор проекта». Пользователь может вернуться к Result кнопкой Back; focus ставится в осмысленное начало выбора, не на случайную строку проекта.

## 10. Клавиатура и focus

### 10.1. Правила focus

Все действия доступны обычной аппаратной клавиатурой. Tab идёт по визуально-смысловому порядку; Shift+Tab возвращает назад. Enter/Space активируют кнопки по платформенному паттерну, а в многострочном тексте Enter вставляет перевод строки. Недоступные controls не создают бесполезные Tab-stop; причина недоступности остаётся читаемой.

Focus ring: 2 dp, offset 2 dp, промежуток цвета текущего фона; token `focus.ring`. Он не обрезается clip карточки, родительским scroll container или краем окна. Hover и focus независимы: pointer hover не убирает keyboard ring. Базовый focus без анимации уже различим.

При открытии sheet/dialog focus входит в него: на заголовок/первое содержательное поле, для разрушительного подтверждения — на безопасную команду. Tab не уходит в background; Escape/системный Back закрывают отменяемый слой. После закрытия focus возвращается к вызывавшей кнопке; если объект удалён — к следующей строке списка либо header пустого состояния.

Нижняя sticky-панель, toolbar и IME не перекрывают focused control. Для Kasha принят более сильный критерий: target с ring виден полностью, когда пользователь перешёл к нему клавиатурой. Это развивает минимальное требование отсутствия полного перекрытия focus в [W3C Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html).

### 10.2. Управление без специальных сочетаний

| Контекст | Клавиши/действие |
|---|---|
| Обычная кнопка | Enter/Space по платформенному паттерну |
| Switch/completion | Space изменяет значение; состояние объявляется |
| Меню сортировки | Стрелки между пунктами, Enter выбрать, Escape закрыть |
| Ползунок качества | Стрелки на одну ступень; Home/End крайние значения |
| Скорость сохранения | Стрелки по 0,25×; текущее значение озвучивается |
| Seek аудио | Стрелки по 5 секунд; Home начало, End конец; значение ограничено длительностью |
| Editable text | Стандартные выделение, копирование, вставка, отмена и redo |
| Sheet | Escape/Back отменяет закрываемый слой; при несохранённых правках запускает соответствующее подтверждение |
| Task row | Enter открывает редактор, Space у сфокусированного completion меняет только completion |

Глобальный Space не запускает/останавливает запись, пока focus в тексте или неизвестной области. Горячие клавиши поверх печати не вводятся без явного дизайна и видимой документации. Native undo текста не должен выполнять «восстановление удалённой задачи» из другого слоя.

### 10.3. Подсказки при hover и focus

Подсказка icon button доступна и при наведении мыши, и при focus с клавиатуры. Она закрывается Escape без перемещения focus; указатель может перейти на саму подсказку, не заставляя её исчезнуть. Она остаётся открытой, пока сохраняется hover/focus и пользователь не закрыл её. Нужная инструкция не существует только в tooltip: на touch-экране действие имеет accessible label, при неоднозначном glyph — видимую подпись либо раскрываемое пояснение. Подсказка не закрывает сфокусированную кнопку. Эти условия соответствуют [W3C Content on Hover or Focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html).

### 10.4. Focus при обновлениях

Поллинг snapshot, смена timer, progress, model-state и завершение фоновой обработки не сбрасывают Tab на начало страницы. Каждый row/control имеет устойчивый ID сущности, а не индекс текущей сортировки. После completion и переноса в Archive focus уходит на следующую активную задачу; если её нет — heading/пустое состояние с объявлением выполнения.

Автосохранение текста не восстанавливает старое выделение поверх нового ввода. Подтверждение ошибки не перерисовывает экран отдельным Notice, скрывающим editor. Перестановка pinned/manual сохраняет идентичность сфокусированной строки.

## 11. Touch, pointer и перестановка без drag

Kasha устанавливает минимум target 44×44 dp, предпочтительно 48×48 dp; это внутреннее усиление поверх WCAG 2.2 AA Target Size Minimum, у которого базовый порог 24×24 CSS px с оговорёнными исключениями. Не называть 44 dp универсальным порогом AA. См. [W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

Touch target может быть больше видимого glyph, но соседние target не перекрываются и pointer hit-testing однозначен. Между самостоятельными icon targets желательно 8 dp; для соседних 48 dp tab-зон допустима общая граница при равных областях. Нажатие срабатывает на отпускании внутри target; уход пальца отменяет случайную активацию, кроме специально спроектированного drag.

Long press для manual reorder — 500 ms по умолчанию до lift, с приоритетом доступной системной настройки жеста; micro-motion и haptic по [08](./08-graphics-motion.md). Обычный вертикальный скролл до long-press не переставляет элементы. Во время drag автопрокрутка у края не прыгает на несколько экранов. Отмена возвращает строку к исходному месту без сохранения промежуточных позиций.

**Обязательная альтернатива:** в режиме «Вручную» row menu содержит «Переместить выше», «Переместить ниже», при длинном списке «В начало» / «В конец». Те же действия доступны screen reader как custom actions и клавиатуре через контекстное меню. На первой/последней позиции соответствующая команда недоступна; после выполнения объявляется «{name}, позиция 3 из 12».

Это один и тот же порядок в Core, а не отдельный keyboard order. Pin-группа переставляется внутри своего списка; команда не переносит элемент через границу pinned/unpinned и не меняет статус закрепления. При сортировке не «Вручную» команды ручного перемещения скрыты, но сохранённый manual order не стирается.

Нельзя делать drag единственным способом действия. Требование соответствует [W3C Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html). Доступный click/menu-путь не требует имитировать удержание курсором.

## 12. Reduce Motion, сенсорная нагрузка и haptics

Системный Reduce Motion читается платформенным адаптером и применяется общим motion-токеном. Для web используется реальное preference окружения, а не user-agent определение. Параллельный собственный переключатель не обязателен: существующая модель настроек его не имеет.

| Эффект | Обычно | Reduce Motion |
|---|---|---|
| Orb breathing | 1,6–2,0 с, мягкий scale | Полностью выключен |
| Glow от RMS | Мягкое изменение интенсивности | Статичный свет; сигнал передаётся функциональной waveform/статусом |
| Навигация/sheet | Переходы из motion-системы | Краткий opacity до 120 ms либо мгновенно |
| Parallax/decor movement | Только если предусмотрен целевым экраном | Выключен |
| Processing phase rotation | Медленное движение | Статичный glyph + текст этапа |
| Task completion morph | 220–320 ms | Мгновенная смена check + короткий opacity |
| Drag lift/spring | Scale 1,015 и spring | Без scale/spring, позиция и target обозначены статично |
| Waveform | Реальная реакция на аудио | Остаётся функциональной, без лишнего bloom/overshoot/синусоидальных выдумок |

Никаких вспышек, строба и внезапного fullscreen glow. Декоративная бесконечная анимация не является единственным указателем работающего процесса. При слабом устройстве/режиме экономии графические эффекты могут уменьшаться независимо от Reduce Motion; recording и audio sampling не зависят от частоты рисования blur.

Haptic — дополнительный канал. Начало/пауза/продолжение/завершение, lift/смена позиции, completion и destructive confirmation имеют визуальный и текстовый эквивалент. Отсутствие вибромотора или отключённые haptics не меняют доступность. Обычная навигация не вибрирует.

## 13. Языки, текст пользователя и направление

В текущем каталоге восемь LTR-языков: русский, английский, испанский, французский, немецкий, украинский, белорусский, казахский. Поддержка интерфейса RTL в этой версии не заявляется и не добавляет девятую локаль. При этом пользователь может вводить арабский/иврит и смешанный текст; Unicode, переносы и корректная обработка bidi в документе обязательны, нельзя удалять символы как «неподдерживаемый язык».

В layout применять start/end вместо hard-coded left/right там, где это семантически начало/конец текста. Back/disclosure могут зеркалиться будущим RTL-адаптером; логотип, микрофон, физический audio waveform и таймер не зеркалятся автоматически. Это подготовка к расширению, а не обещанная полноценная RTL-локализация.

Название locale в языке списка показывается в собственном написании. Page language и язык accessible labels соответствуют выбранной локали. Пользовательский документ не переводится вместе с UI. Даты, десятичные дроби, время и множественные формы форматируются единообразно по [контенту](./09-content-language.md).

Тестировать кириллические `ё`, `ї`, `є`, `ґ`, `ў`, казахские `ә`, `ғ`, `қ`, `ң`, `ө`, `ұ`, `ү`, `һ`, `і`, диакритику и комбинируемые знаки. Fallback font не должен незаметно превращать половину казахского текста в другую гарнитуру. Строки локализации могут удлиняться на 40% относительно русского эталона; layout выдерживает это переносом, а не уменьшением до 9 sp.

## 14. Платформенные границы

Системные диалоги разрешений, share/file/date/time pickers, системное меню редактирования, spellcheck и менеджер паролей могут использовать native UI. Kasha не должна рисовать поддельный системный prompt и запрашивать OS-permission через собственную галочку. Запрет стандартного Material-вида относится к контролам, которыми владеет приложение, а не к безопасности и assistive technology ОС.

Для Compose каждый пользовательский Canvas-control получает настоящую семантическую роль, value и actions. На web недостаточно визуально отрисовать кнопки на canvas: accessibility tree должен быть доступен браузеру/скринридеру. Если текущий renderer не обеспечивает необходимую семантику, это блокирующая задача платформенного слоя до заявления AA, а не повод считать скриншот проверкой.

| Платформа | Минимальная ручная проверка | Что нельзя предполагать |
|---|---|---|
| iOS/iPadOS | VoiceOver, Dynamic Type 200%, клавиатура, portrait/landscape/Split View, разрешения | Что существующий Compose label автоматически правильно прочитан VoiceOver |
| Android при наличии целевого адаптера | TalkBack, font/display scaling, жестовая/трёхкнопочная навигация, Back | Что iOS-разрешения и поведение записи в фоне переносятся без изменений |
| macOS/Desktop | Клавиатура, focus ring, resize, screen reader платформы, titlebar insets | Что центрированный mobile-layout является desktop-адаптацией |
| Web | Браузерная клавиатура, accessibility tree, zoom/reflow, screen reader на поддержанном сочетании | Что включённый `overflow:hidden` и canvas снимают требования доступности |
| Windows/Linux при наличии сборки | Клавиатура, масштаб ОС, accessibility bridge, разрешения аудио/уведомлений | Что общий Kotlin-код доказывает готовность платформенной поддержки |

Матрица не объявляет Android/Windows/Linux готовыми релизами. Состав реально поддержанных платформ и адаптеров фиксируется [картой репозитория](./01-repository-map.md); доступные функции подчинены ей.

## 16. Проверяемые критерии выпуска

- **ADAPT-01:** отсутствие жёсткой общей ширины 430 dp как единственной схемы на desktop; breakpoint определяется доступным окном.
- **ADAPT-02:** при 320 dp и 200% текста доступен весь ключевой flow: запись → пауза → завершить → исправить текст → В заметки/В задачи → сохранить.
- **ADAPT-03:** навигация при переполнении становится 2×2 одной поверхностью; ни одна label не скрыта многоточием.
- **ADAPT-04:** клавиатура и player не перекрывают focused field/caret; после последней строки есть реальный scroll padding.
- **ADAPT-05:** resize/rotate/split не дублируют repository, запись, сохранение либо модель редактируемой сущности.
- **A11Y-01:** все самостоятельные controls ≥44×44 dp, основная цель 48 dp; области попадания соседних действий не пересекаются.
- **A11Y-02:** смысловой текст проходит 4,5:1, значимые controls — 3:1 на фактическом фоне в обеих темах и состояниях; hairline не единственный признак.
- **A11Y-03:** screen reader выполняет полный flow без waveform-bars, дублирующих labels и технического `global-player` в озвучке.
- **A11Y-04:** таймер, прогресс загрузки и фоновый polling не прерывают чтение и не сбрасывают focus.
- **A11Y-05:** каждый drag имеет click/keyboard/screen-reader альтернативу, меняющую тот же сохранённый порядок.
- **A11Y-06:** focus ring 2 dp + offset 2 dp виден, не обрезан и не перекрыт нижними панелями; закрытие modal возвращает focus.
- **A11Y-07:** Reduce Motion выключает дыхание, glow-animation, parallax и spring; функциональная waveform и статусы остаются.
- **A11Y-08:** ошибки, selected, recording/paused, completed и external не определяются одним цветом.
- **A11Y-09:** locale fallback, казахская/украинская/белорусская кириллица и длинные строки не ломают Geologica и layout.
- **A11Y-10:** OS permissions и native pickers доступны системным средствам; UI не обещает неподдерживаемые background/STT/notification возможности.

Нормативная база общих критериев — [WCAG 2.2 W3C Recommendation](https://www.w3.org/TR/WCAG22/). Внутренние размеры Kasha, навигация 2×2, конкретные breakpoints и правила композиции являются решениями этого ТЗ; они не приписываются W3C. До ручной проверки целевых платформ и полного аудита страницы нельзя писать в продукте «полностью соответствует WCAG AA» только на основании цветов и автоматических тестов.
