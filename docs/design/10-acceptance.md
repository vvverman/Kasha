# 10. Приёмка дизайна и поведения

## 1. Как принимать

Этот документ определяет **будущую проверку реализации**. Галочки здесь не означают, что текущий `main` или iOS PR прошли проверку на устройстве. Фактическая проверка комплекта документации хранится отдельно в `VALIDATION.md` после выполнения.

Для каждой проверяемой сборки фиксируются commit, платформа/версия ОС, размер окна, scale/density, размер текста, язык, тема, реальные/демонстрационные адаптеры и выбранные AI-роли. Одного красивого скриншота iPhone недостаточно для приёмки общего UI.

## 2. Минимальная матрица визуальных состояний

| Экран | Обязательные состояния | Дополнительный стресс-сценарий |
|---|---|---|
| Сплеш | Фирменный solid-знак, макрофон, процедурный fallback | Нет изображения, Reduce Motion, холодный старт |
| Главная idle | Без pending, без готового capture, разрешённая/запрещённая запись | Короткое окно с safe area; авто-record выключен |
| Главная recording | Тишина, тихая речь, громкий сигнал, пауза, продолжение | 60+ минут; возвращение из другой вкладки |
| Processing | STT, подготовка аудио, tidy, NEEDS_MODEL, FAILED | Длительная операция без достоверных процентов |
| Result | Короткий и длинный текст, редактирование, saving, save error | 10 000 символов, клавиатура, 200% текста |
| Global Player | Запись/пауза/завершение, playback idle/playing/paused/stop | Название 150 символов; длительности не совпадают с исходником |
| Проекты | Пусто, обычный список, pinned, 4 сортировки | 100 проектов, одинаковые названия, drag у края |
| Проектный picker | Без рейтинга, с рейтингом, ошибка routing, новый проект | Назначение не меняет пользовательский порядок проектов |
| Заметки проекта | Пусто, список, pin, audio glyph, 4 сортировки | Очень длинная первая строка, источник отсутствует |
| Заметка | Чтение/редактирование, 0/1/несколько источников | Несохранённая правка, смена источника при записи |
| Задачи | Пусто, активные, ближайшие сроки, выполнение | Перенос просроченного срока, ошибка commit выполнения |
| Архив | Пусто, выполненные, чтение задачи | Нет незаконной кнопки восстановления без контракта |
| Расписание задачи | Выбор даты/времени/повтора, ошибка, saving | Изменение timezone, DST, разрешение notifications отклонено |
| Настройки | 4 группы и «О приложении», системная/светлая/тёмная темы | Все 8 языков; очень узкое окно |
| AI роль/модель | Local/external, installed/available/downloading/error | Модель выбрана, но адаптер её не исполняет |
| Внешний сервис | Не подключён, согласие, проверка, ошибка, отключён | Смена endpoint, отзыв согласия во время операции |

Полный набор состояний каждого экрана определён в соответствующем разделе. Матрица показывает минимальные визуальные доказательства, а не заменяет спецификацию.

## 3. Критерии визуальной системы

| ID | Проверка | Условие приёмки |
|---|---|---|
| VIS-01 | Бренд | В UI используется существующий знак; исходные SVG совпадают побайтно с базой; нет текстовой подмены |
| VIS-02 | Шрифт | Geologica действительно загружается локально; применены документированные оси; проверены 8 алфавитов и `tnum` |
| VIS-03 | Размеры текста | Продуктовый текст не меньше 11sp; body и hierarchy соответствуют токенам; 200% не обрезает действия |
| VIS-04 | Темы | Dark/Light используют семантические токены; fallback/system theme корректны; палитра не становится сине-фиолетовой |
| VIS-05 | Контраст | Текст и контроли проверены после alpha-compositing на фактических поверхностях; AA из раздела доступности |
| VIS-06 | Пространство | Использованы общие spacing/radius tokens; нет Card-in-Card и растянутой phone-column на любом desktop |
| VIS-07 | Навигация | Одна поверхность; 4 пункта, видимый активный label/glyph, без центрального FAB |
| VIS-08 | Иконки | Один реестр; 24 grid, целевой stroke, 20/24/32 читаемы; отсутствуют сторонние glyphs и MAGIC-звёзды |
| VIS-09 | Сплеш | Фото гречки только здесь; логотип отдельным SVG; изображение не задерживает готовый интерфейс |
| VIS-10 | Процедурная графика | Orb, фон, glow, waveform, controls не заменены картинками; в Reduce Motion сохраняются понятные состояния |
| VIS-11 | Анимация | Длительности и амплитуды соответствуют tokens; нет вечного motion у обычных иконок и двойного bounce |
| VIS-12 | Плотность | Result отдаёт место тексту; запись — waveform; idle — orb; в кадре нет всех трёх состояний одновременно |

## 4. Сквозные пользовательские сценарии

| ID | Действия | Ожидаемый результат |
|---|---|---|
| UX-01 | Холодный запуск с разрешённым autoRecord, затем фон/возврат | Не более одной активной сессии; возврат не создаёт новую; pending имеет приоритет |
| UX-02 | Начать запись → говорить → пауза 20 секунд → продолжить | На паузе сохраняются форма waveform и elapsed; при продолжении идут новые данные |
| UX-03 | Во время записи открыть Проекты, заметку, Задачи, вернуться | Одна и та же сессия; глобальный транспорт доступен; waveform отражает реальный сигнал |
| UX-04 | Из записи запросить playback другого источника | Есть понятное подтверждение; текущая запись сохраняется; никогда не активны два аудиопроцесса |
| UX-05 | Отменить запись и отказаться от подтверждения | Явная команда возврата восстанавливает прежнее recording/paused; системный Back/свайп оставляет безопасную паузу; данные не удалены |
| UX-06 | Подтвердить отмену записи | Реальный recorder завершён и освобождён, временный файл удалён безопасно; UI возвращается в idle |
| UX-07 | Завершить запись с рабочим STT | Реальные стадии → редактируемый текст; нет фиктивного streaming-текста |
| UX-08 | STT не установлен/запрещён/ошибся | Причины различаются, исходник доступен, retry не создаёт дубль |
| UX-09 | Править текст → «Привести в порядок» | Числа, имена, отрицания и смысл сохраняются; отказ проверки оставляет оригинал |
| UX-10 | Изменить текст пока приходит старый AI-ответ | Новый пользовательский текст не перезаписан устаревшим результатом |
| UX-11 | «В заметки» → новый проект → новая заметка | Проект и заметка сохранены; название из первой непустой строки; capture привязан один раз |
| UX-12 | «В заметки» → существующая заметка | Предыдущий текст побайтно сохранён как префикс; добавление в конец; отдельный аудиоисточник |
| UX-13 | Двойной тап сохранения / повтор после сетевой задержки локального транспорта | Одна публикация; один source; понятное состояние pending transaction |
| UX-14 | После отправки в заметки попробовать отправить тот же capture в задачи | Нет двойной сущности; UI не предлагает второе сохранение завершённого capture |
| UX-15 | «В задачи» → срок/повтор → сохранить | Одна задача с исходным текстом; автоматическое разделение на несколько задач отсутствует |
| UX-16 | Изменить срок задачи и повтор напоминаний | Используется новое расписание, старое системное уведомление отменено/заменено |
| UX-17 | Выполнить задачу | Короткий визуальный отклик, успешный commit, затем Архив; при ошибке задача остаётся активной |
| UX-18 | Наступление срока и повторных напоминаний | Core и adapter соблюдают документированное правило; не создаются новые задачи; ограничения закрытого приложения честно показаны |
| UX-19 | Ручной порядок → другая сортировка → Manual → перезапуск | Сохранённая расстановка восстановлена |
| UX-20 | Pin/unpin и Manual на проектах/заметках | Закреплённые сверху по pinOrder; unpinned по сохранённому manualOrder; данные не переписаны UI-сортировкой |
| UX-21 | Drag проекта/заметки/задачи + отмена drag | Нет потери/дублей; сохранение только корректного порядка; отмена возвращает исходное состояние |
| UX-22 | То же без drag: клавиатура/screen reader | Все операции перестановки доступны, новая позиция озвучена |
| UX-23 | В заметке изменить первую непустую строку | Заголовок в списке и metadata согласован; нет второго поля title |
| UX-24 | Ошибка сохранения текста | Текст остаётся в редакторе, показан retry; переход не молча теряет правки |
| UX-25 | Аварийно прервать запись → запуск | Восстановление перед autoRecord; elapsed и waveform основаны на файле, не произвольном нуле |
| UX-26 | Сменить язык/тему во время записи | Запись сохраняется; переключение не сбрасывает session/controller |

## 5. Приватность и возможности адаптера

| ID | Проверка | Условие приёмки |
|---|---|---|
| PRI-01 | Local без внешней сети | Исполнимый локальный сценарий работает без отправки пользовательских данных; наличие download-модели не подменяет тест |
| PRI-02 | Выбор роли | STT/TEXT/ROUTING настраиваются независимо и действительно влияют на выбранный adapter |
| PRI-03 | Нет согласия | Внешний запрос с аудио/текстом/проектами не отправлен; кнопка объясняет нужное действие |
| PRI-04 | Состав данных | Consent показывает фактические типы данных; routing description/id учтены, если входят в запрос |
| PRI-05 | Новая область согласия | Смена провайдера, endpoint или состава отправки требует соответствующего нового решения |
| PRI-06 | Отзыв | Новые запросы блокируются; UI не обещает удалить уже доставленные данные у провайдера |
| PRI-07 | Ключ | Нет API-key в Preferences, UI-логах, скриншотах, git-файлах; секрет хранится platform secure storage |
| PRI-08 | Capability | Недоступная модель не маскируется под рабочую; iOS deterministic fallback не называется полноценной LLM |
| PRI-09 | Демонстрация | Текст и звук правдиво обозначены как реальные или тестовые по отдельности |

## 7. Размеры и нагрузка для проверки

Обязательные компактные окна: 320×568, 360×800, 390×844, 430×932 логических единиц. Проверить также короткое landscape-окно, 768×1024, 1024×768 и 1440×900. Это размеры тестовой области, не обещание конкретной модели устройства. Для каждого класса минимум тёмная/светлая темы; для наиболее узкого и широкого — 200% текста.

Основные фикстуры: пустые данные; 100 проектов; 500 заметок в проекте; 500 активных задач; 10 источников в заметке; документ 10 000 символов; строка 500 символов без пробелов; emoji и смешанная кириллица/латиница; waveform тишины, импульса, тихой речи, насыщения и часовой записи.

Виртуализация списков не должна сбрасывать focus/reorder state. Перерисовка waveform не вызывает пересборку всего списка. Производительность измеряется на реальной целевой платформе с активным аудио; budget и degradation определены в [графике](08-graphics-motion.md). Не объявлять FPS по настольному HTML-каталогу доказательством скорости iOS Compose.

## 8. Какие проверки автоматизировать

В существующих Core/UI тестах расширять проверки по изменяемому риску: idempotent append, закрепление в Manual, отмена recorder, независимое исполнение ролей, privacy scope, reminder lifecycle, остановка timeline на pause. Не писать тест, который только повторяет значение константы ради покрытия.

Для изображений/screenshots применять одинаковую density, реальные локальные шрифты и детерминированные данные. Декоративный noise должен иметь фиксированный seed в visual tests. Визуальные снимки не заменяют keyboard/semantics и проверку транзакций.

Существующие архитектурные guards (`check-ui-boundary.py`, `check-brand-boundary.py`, `check-local-only.py`, `check-ai-boundary.py`) и существующие CI из общего ТЗ остаются обязательными для функционального внедрения. Ссылки на точные тесты — в [карте репозитория](01-repository-map.md).

## 9. Стоп-критерии выпуска

Блокируют выпуск: потеря аудио/текста, внешняя передача без согласия, два одновременных аудиопроцесса, ложная поддержка функции, недоступные основные действия при 200%, сломанный focus, дублирующее сохранение, подмена логотипа, сторонний icon pack, критически нечитабельный контраст. Отсутствие необязательного макрофона не блокирует запуск при корректном процедурном fallback.
