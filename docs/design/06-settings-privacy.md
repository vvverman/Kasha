## 2. Общая композиция SETTINGS-01

Экран называется «Настройки». H1 30/35, ширина и поля — по адаптивной сетке. После заголовка 24 dp до первой группы. Между группами 28 dp; между заголовком группы и её поверхностью 10 dp. Внутри группы одна Surface с радиусом 20 dp; строки разделяются отступами и hairline, отдельной карточки на каждую строку нет.

Состав сверху вниз:

1. **Запись:** «Начинать запись при запуске», «Параметры аудио», настройка предложения проекта после расшифровки.
2. **AI:** «Распознавание речи», «Обработка текста», «Подбор проекта».
3. **Интерфейс:** «Тема», «Язык приложения».
4. **Приватность:** сводка места обработки, «Внешние подключения», «Разрешения устройства».
5. **О приложении:** версия и при необходимости отметка тестового режима.

Строка с одной строкой текста имеет `minHeight=56 dp`; с пояснением — `minHeight=76 dp`. Внутренние поля 16 dp по горизонтали, 12 dp по вертикали. Leading glyph 22 dp, после него 12 dp. Заголовок Body 16/23, пояснение Body Small 14/20, интервал 3 dp. Trailing control занимает минимум 48×48 dp. Значение длиннее 24 символов переносится под заголовок, а не сжимает основной текст. Chevron означает открытие вложенного экрана, switch — изменение на месте; их нельзя ставить одновременно у одной строки.

Сводку приватности не превращать в большую постоянную предупреждающую карточку. В группе достаточно читаемой строки «Все активные функции выполняются на устройстве» либо «Есть внешняя обработка: распознавание речи, подбор проекта». Текст строится по реальному исполнению, а не только `Preferences`.

Внизу обычной страницы остаются общая навигация и активный Global Player. Состояние записи сохраняется при любом переходе в настройки. Вложенные редакторы не останавливают микрофон сами по себе.

## 3. Сохранение обычных настроек

Переключатели, язык, тема и завершённое перемещение ползунка сохраняются сразу. Общей кнопки «Сохранить всё» нет. В UI существуют состояния `stable`, `saving`, `error`; их нельзя заменять полноэкранной ошибкой вместо всей страницы.

| Состояние | Отображение | Поведение |
|---|---|---|
| Сохранено | Обычное значение; без постоянного зелёного check | Последующее открытие и перезапуск показывают это же значение |
| Сохраняется <400 ms | Новый видимый выбор, без мерцания индикатора | Другие настройки доступны; повтор того же запроса не создаётся |
| Сохраняется ≥400 ms | Под затронутой строкой «Сохраняем…» 14/20 | Серия изменений одного поля объединяется до последнего значения |
| Ошибка | «Не удалось сохранить. Повторить» под строкой; причина по возможности конкретная | Хранить введённое значение как несохранённое; показать прежнее сохранённое при необходимости, не выдавать новый выбор за сохранённый |
| Уход со страницы при ошибке | Неблокирующая строка «Изменение не сохранено» и команда «Повторить» | Если пользователь хочет отбросить неудачное изменение, вернуть последнюю подтверждённую настройку |

Для реализации существующий `savePreferences(value)` необходимо вызывать с актуальным состоянием, а не с устаревшим `p`, захваченным несколькими параллельными обработчиками. Изменение темы и языка не должно перезаписать только что выбранную AI-модель или сортировку. Сохранение обычных параметров и редактора ключа — разные транзакции.

AI-выбор и передача данных применяются только после подтверждённого сохранения. Оптимистическое сообщение «Локально» до изменения маршрута недопустимо. Изменение параметров не переписывает сохранённое аудио и готовые тексты; подпись «Применится к следующим записям» показывается там, где это существенно.

## 4. Запись SETTINGS-02

### 4.1. «Начинать запись при запуске»

Пояснение: «Начинает новую запись, когда вы открываете Kasha и нет незавершённой записи». Значение берётся из `Preferences.autoRecord`; исходное значение Core — включено, специальная тестовая iOS-сборка его выключает. Не сбрасывать настройку обновлением дизайна.

Термин «при запуске» означает первую инициализацию приложения, а не каждое открытие вкладки «Главная», возврат после системного диалога или каждой фоновой паузы. Pending audio и уже существующий результат имеют приоритет. Предыдущая запись сначала восстанавливается; автозапуск не затирает её и не создаёт вторую сессию.

При первом запуске до системного согласия на микрофон показывается краткое объяснение и явная команда «Разрешить микрофон». Включённая настройка не даёт права обходить системный диалог. Если разрешение отклонено: «Автозапуск включён, но доступ к микрофону запрещён», команда «Разрешения устройства». Пояснение не отключает switch молча; пользовательская настройка и возможность её исполнить — разные состояния.

При попытке включить опцию на адаптере без реальной записи показывать «В этой сборке используется демонстрационная запись», switch недоступен. До подключения платформенной реализации не рисовать активный микрофон.

### 4.2. «Параметры аудио»

Открывает отдельную страницу `SETTINGS-AUDIO`. Первый блок — «Качество сохранённого аудио». Содержит текущую ступень, короткое пояснение, дискретный ползунок и четыре достижимые клавиатурой позиции. Высота интерактивной области ползунка 48 dp, дорожка 3 dp, thumb 20 dp, активный target 48 dp. При изменении голосовой вывод сообщает название ступени и значение.

| `quality` | Надпись | Соответствующий `Preferences.bitrate` |
|---|---|---|
| 0 | Экономное | 32 кбит/с |
| 1 | Обычное | 48 кбит/с |
| 2 | Высокое | 64 кбит/с |
| 3 | Максимальное | 96 кбит/с |

Подпись: «Влияет на размер сохранённого аудио. Исходную запись для распознавания не меняет». Она применима к JVM-пайплайну: [StudioProcessing.kt](../../runtime/src/main/kotlin/brain/runtime/StudioProcessing.kt) кодирует подготовленное аудио. Не утверждать, что более высокий битрейт автоматически повысит точность распознавания. Не показывать точный размер будущего файла без фактической оценки.

Второй блок через 24 dp — «Скорость сохранённого аудио». Значения: 1×, 1,25×, 1,5×, 1,75×, 2×. Текущее значение справа с tabular figures, Body 16/23. Подпись: «Ускоряет подготовленное аудио при сохранении. Обычное воспроизведение исходника сохраняется отдельно, если его предоставляет платформа». Это не глобальное ускорение воспроизведения: значение `savedSpeed` в JVM используется при создании компактного аудио через `atempo`.

Третий информационный блок появляется только при реально поддерживаемой подготовке: «Подготовка аудио» и описание удаления тишины. Не добавлять switch удаления тишины: такого пользовательского параметра сейчас нет. Не обещать возможность восстановления исходника, если конкретная сборка его не сохраняет.

В iOS PR #9 записывается AAC mono 44,1 кГц без применения `quality` и без JVM-подготовки со `savedSpeed`. На такой сборке эти две настройки не должны выглядеть действующими: показать строку «На этом устройстве запись сохраняется с системными параметрами»; сохранённые общие значения оставить в данных для совместимости. Значения открываются для изменения только после capability подтверждённого кодировщика.

### 4.3. Подбор проекта после расшифровки

Исходный `autoRoute=false`. Текущий `StudioState.refresh` при включении только открывает экран выбора проекта после получения READY; он **не сохраняет заметку автоматически**. Не называть это «Автоматически сохранять в проект».

Целевое название: «Открывать выбор проекта после расшифровки». Пояснение: «После расшифровки откроется выбор проекта. Сохранение нужно подтвердить». Сохраняется текущее поведение: после READY экран назначения открывается один раз для записи; проект не выбран, заметка не создана. «Назад» возвращает Result с двумя отдельными командами «В заметки» / «В задачи». Повторное посещение Result не открывает выбор заново. Подбор подходящего проекта использует роль Routing только при наличии подходящего движка и, для внешнего исполнения, действующего согласия. Точный переход задан в [записи и плеере](./04-capture-player.md).

Нет проектов — предложение не запускается, создание проекта остаётся доступно при сохранении. Routing недоступен — ручной выбор остаётся доступен, switch не обещает автоматический результат. Ошибка ранжирования не блокирует текст и не подставляет случайный проект. Внешний Routing требует согласия на текст и данные проектов, даже если STT и Text остаются локальными.

## 5. Три независимые AI-роли SETTINGS-03

На первом уровне всегда три строки с одинаковой структурой: название функции, реально используемый механизм, место обработки, статус при проблеме. В интерфейсе русские названия; enum и технические ID нужны в документации и диагностике, а не вместо продуктового текста.

| Роль | Название | Что делает | Что не делает |
|---|---|---|---|
| `SPEECH_TO_TEXT` | Распознавание речи | Превращает запись в текст | Не переписывает стиль заметки и не выбирает проект |
| `TEXT` | Обработка текста | Выполняет «Привести в порядок» | Не отправляет текст в проект и не разбивает одну запись на много задач |
| `ROUTING` | Подбор проекта | Оценивает соответствие текста существующим проектам | Не меняет текст, не создаёт проекты и не сохраняет за пользователя |

Одна модель может поддерживать Text и Routing, но выбор остаётся раздельным. Назначение Qwen для обработки не меняет подбор проекта. Замена Speech не меняет остальные строки. Если пакет используется двумя ролями, на диске это один пакет: загрузка и объём не дублируются.

Варианты подписи места: «На устройстве», «Системное распознавание на устройстве», «Внешний сервис · {provider}», «Демонстрационный режим». `NATIVE` само по себе не доказывает обработку без сети: показывать локальность только по явно обеспеченному адаптером режиму. В iOS PR `requiresOnDeviceRecognition=true`, поэтому при неподдерживаемом языке необходима ошибка, а не скрытый переход к сетевому Apple Speech.

Состояния строк: «Готово», «Модель не установлена», «Не поддерживается на этом устройстве», «Нужно разрешение», «Подключение отключено», «Нужно подтвердить передачу», «Не удалось проверить состояние». Не использовать общий зелёный check рядом с неизвестным состоянием.

### 5.1. Страница выбора AI-ROLE

Header: Back 48×48 dp, название роли H2 25/30. Под ним 12 dp, описание функции Body 16/23, затем 24 dp до списка. Выбранный механизм вверху списка имеет check 20 dp и подпись «Выбрано»; акцентная заливка всей строки не нужна.

Секции: «На устройстве» и «Подключённые сервисы». Новый внешний сервис открывается одной командой «Подключить внешний сервис», без набора ярких рекламных логотипов. Доступные механизмы поступают из объединения каталога и возможностей текущего адаптера. Списка всех известных движков без проверки поддержки недостаточно.

Model row: `minHeight=88 dp`, поля 16 dp, имя 16/23, версия/описание 14/20, состояние отдельной строкой. В 320–359 dp кнопка действия переносится вниз с выравниванием по началу. Внешнее название модели не обрезается до неразличимого префикса: допускается две строки и раскрытие полного ID.

Пример локальной строки: «Whisper Small» / «Около 500 МБ · Распознавание речи» / «Не установлен» / «Скачать». Размер берётся из каталога как приблизительный, после установки — фактический, если его предоставляет платформа. Метки «самый точный» и «лучший» без измерений на поддержанных языках не являются UI-копирайтом.

### 5.2. Жизненный цикл локальной модели

| Состояние | Видимое содержание | Действие и результат |
|---|---|---|
| Определяется | «Проверяем доступность…», статичный glyph | Список остаётся читаемым; нельзя выбрать непроверенный пункт |
| Не поддерживается | «Недоступно на этом устройстве» + конкретная причина | Не показывать «Скачать» |
| Требует условия лицензии | «Для установки нужны условия модели» | Переход к условиям только если полный процесс реализован; Gemma с `installable=false` не выдавать за скачиваемую |
| Не установлен | Размер и «Скачать» | До сетевого запроса сообщить объём; не открывать системные разрешения, не относящиеся к загрузке |
| Скачивается, известен объём | «Скачиваем · 42%», линейный прогресс 3 dp | Повторное нажатие исключено; уход со страницы не начинает повторную загрузку |
| Скачивается, объём неизвестен | «Скачиваем…» + движущийся неброский индикатор | Не показывать выдуманный процент и не держать ложные 0% |
| Проверяется | «Проверяем модель…» | 100% загрузки ещё не означает готовность к использованию |
| Установлен и исполняется адаптером | «На устройстве», «Выбрать» | Сохранить только выбранную роль; после успеха check |
| Установлен, но runtime не запускается | «Модель загружена, запуск недоступен» + причина | Не маркировать Ready; восстановление/другой механизм |
| Ошибка сети | «Загрузка прервана. Попробовать снова» | Сохранить прежний выбранный движок; повтор по действию пользователя |
| Недостаточно места | «Недостаточно места для модели» + требуемый объём, только если известен | Предложить удалить другой необязательный пакет; не удалять его автоматически |
| Ошибка проверки файла | «Не удалось проверить модель. Скачайте снова» | Повреждённый пакет не становится доступным |
| Удаляется | «Удаляем…» | Строка остаётся на месте до результата |
| Ошибка удаления | «Не удалось удалить модель» | Не уменьшать показанный занимаемый объём до подтверждения |

Существующий API не имеет `cancel` и не сообщает отдельные состояния verify/runnable. Это целевые расширения платформенного состояния; пока они не реализованы, не рисовать неработающие «Пауза загрузки» / «Отмена». Достаточно правдивого «Скачиваем…», затем подтверждённого результата. Целевой обновляемый прогресс поступает через поток либо опрос не чаще 2 раз/с, когда экран виден; процент озвучивается редко, не на каждом изменении.

Удаление встроенного пакета запрещено платформой: подпись «В составе приложения», без активной команды удаления. Удаление выбранного необязательного пакета требует сначала выбрать реально готовую замену для всех использующих его ролей. Если замены нет: «Эта модель используется. Сначала выберите другой способ обработки» и «Выбрать замену». Удаление не затрагивает записанный звук, заметки, задачи и тексты прошлых результатов.

При смене модели во время обработки текущий запрос завершается на механизме, с которым стартовал. Следующий этап и новый запуск используют сохранённый выбор только после повторной проверки согласия. В UI рядом с изменением: «Для следующих запусков обработки». Не показывать текущему запросу новое имя провайдера задним числом.

## 6. Внешние подключения SETTINGS-04

### 6.1. Список и возможности

Верх: «Внешние подключения», затем пояснение: «Вы можете выбрать внешний сервис отдельно для каждой функции. Данные отправляются только для выбранных действий». Далее одна Surface со строками подключений. В пустом состоянии: «Внешние сервисы не подключены», Quiet-пояснение локального режима и одна Primary «Подключить сервис».

Каталог описывает следующие роли; это ограничения текущего адаптера Kasha, а не утверждение обо всех возможностях поставщика:

| Сервис | Speech | Text | Routing | Адрес вводится |
|---|---|---|---|---|
| OpenAI | Да | Да | Да | Нет, фиксирован адаптером |
| Anthropic Claude | Нет | Да | Да | Нет |
| Google Gemini | Нет | Да | Да | Нет |
| OpenRouter | Нет | Да | Да | Нет |
| OpenAI-compatible | Нет | Да | Да | Да |
| Custom endpoint | Да | Да | Да | Да |

Текущая идентичность подключения — `providerId`: второе соединение того же provider заменяет существующее. Пока модель данных не расширена, интерфейс не предлагает два независимых OpenAI-подключения. Вместо «Добавить ещё» для такого provider — «Изменить подключение».

Статусы: «Не подключён», «Сохранено, не проверено», «Подключение доступно», «Проверка не удалась», «Ключ отсутствует», «Согласие устарело», «Недоступно в этой сборке». Сохранённое подключение не означает, что оно выбрано для любой роли. Под ним показывать «Используется: обработка текста» либо «Не используется».

### 6.2. Редактор подключения AI-CONNECTION

На мобильном — отдельная прокручиваемая страница; на desktop допустима панель 560–640 dp. Это длинная форма, её нельзя раскрывать под последней строкой настроек так, чтобы начало потерялось выше экрана.

Порядок полей:

1. Название сервиса и поддерживаемые функции, только чтение.
2. Для каждого выбранного пользователем назначения — «Модель для распознавания речи», «Модель для обработки текста», «Модель для подбора проекта». Пустое поле означает, что эта роль не подключается. Подпись объясняет это один раз.
3. «Адрес API» для собственных серверов; для фиксированного адаптера — читаемый фактический домен.
4. «API-ключ». Введённое значение скрыто; Show/Hide 48×48 dp с семантическими названиями «Показать ключ» / «Скрыть ключ». Разрешены вставка и менеджер паролей; автокоррекция, автоматическая капитализация, подсказки слов и запись значения в диагностику отключены.
5. Карточка «Что будет передаваться», построенная из заполненных ролей; ссылка «Проверить разрешение передачи» ведёт к отдельному consent-состоянию.
6. «Проверить подключение» — Secondary; «Сохранить подключение» — Primary. На узком экране кнопки идут вертикально с промежутком 8 dp.
7. Для существующего подключения внизу через 24 dp — «Отключить сервис».

У уже сохранённого ключа поле пустое с подписью «Ключ сохранён. Введите новый, чтобы заменить». Не вставлять фиктивные звёздочки в поле как настоящее значение. Пустая отправка сохраняет существующий ключ в текущем gateway. Для нового подключения ключ обязателен; disabled Save поясняется под соответствующим полем.

Валидация запускается после выхода из заполненного поля либо явного Save, не ругается на нетронутую форму. Ошибки: «Укажите хотя бы одну модель», «Введите API-ключ», «Укажите адрес API», «Используйте HTTPS. Для localhost разрешён HTTP». URL проверяется структурно: схема и точный host, без userinfo; текущего `startsWith("http://localhost")` недостаточно как правила приемки. Домены, лишь начинающиеся на localhost, не считаются локальным адресом.

API-ключ не переносится автоматически на другой host. После изменения адреса уже проверенное соединение становится «Не проверено». При отмене формы черновик ключа очищается; сохранённое соединение остаётся прежним. Несохранённые правки закрываются через «Продолжить редактирование» / «Не сохранять».

## 7. Осознанное согласие PRIVACY-01

### 7.1. Согласие — отдельное состояние

Нельзя ограничиваться маленькой строкой внизу формы и нельзя заранее включать разрешающий switch. Перед первым запросом с пользовательскими данными показать страницу либо крупный sheet «Разрешить передачу данных {provider}?». Header H2, основной текст Body, читаемая Surface и конкретные строки. В 320 dp и при 200% текста — полноценная страница.

Состав:

- Получатель: имя сервиса и полный host/значимый путь API. Для посредника вроде OpenRouter объяснить, что выбранная модель может обслуживаться другим провайдером; точное дополнительное имя показывать только когда адаптер его знает.
- Функции: отмеченные роли, каждая отдельной строкой.
- Данные: точный перечень ниже; описание содержимого без автоматического раскрытия всей личной заметки на странице согласия.
- Когда: «При распознавании записи», «Когда вы нажимаете “Привести в порядок”», «При подборе проекта, в том числе автоматически, если вы включили эту настройку».
- Сохранность локального результата: «Ваши записи и тексты остаются в Kasha. Для обработки сервис получает копию перечисленных данных». Это не обещание синхронизации или резервного копирования.
- Отзыв: «Разрешение можно отозвать в Настройки → Приватность → Внешние подключения».
- Ссылка на условия обработки конкретного сервиса, если актуальный адрес поставляется конфигурацией приложения. Не утверждать отсутствие обучения, определённые сроки хранения, юрисдикцию либо end-to-end encryption без проверенного основания.

Действия: Primary «Разрешить для выбранных функций», Secondary «Оставить на устройстве». После подтверждения возврат в редактор с видимым «Передача разрешена для: …»; Save остаётся отдельным сохранением подключения. Разрешение не выбирает автоматически все роли и не отправляет накопленные записи.

### 7.2. Фактический состав данных

| Роль | Что раскрываем | Служебные данные |
|---|---|---|
| Speech | Аудиофайл выбранной записи | Указанный язык распознавания, имя выбранной модели, параметры запроса и имя файла, если отправляются адаптером |
| Text | Текущий текст, который пользователь отправляет на обработку | Инструкция обработки и имя модели; в legacy-пути также возможен вызов генерации заголовка по этому тексту |
| Routing | Текущий текст; названия, описания и инструкции проектов, участвующих в подборе | Служебные ID этих проектов, имя модели, инструкция ранжирования |
| Проверка подключения | API-ключ/авторизация и запрос метаданных сервиса | Сетевые метаданные запроса; в текущем JVM-тесте личные записи, аудио и проекты не отправляются |

Сетевые метаданные внешнего обращения включают то, что получает удалённый сервер от обычного соединения; не писать «отправляется только текст» в абсолютном смысле. Записи других заметок и задач не добавлять в контекст «на всякий случай». Если набор проектов ограничен фильтром, согласие описывает фактически выбранный набор. Если передаются все проекты, прямо писать «данные всех проектов для подбора».

Текущий `AiPrivacy.dataFor` необходимо расширить/уточнить перед выпуском, поскольку перечисление не полностью соответствует routing payload. Privacy UI обязан строиться из одного контракта передачи с адаптером, а не из вручную написанного сокращённого списка, расходящегося с сетевым запросом.

### 7.3. Привязка согласия и повторная проверка

Целевой объект подтверждения включает версию disclosure, provider, нормализованный адрес получателя, роли, ID моделей и категории данных. Это расширение нынешнего `privacyConsentVersion: Int`, а не описание уже готовой реализации. Хранить безопасный снимок разрешённой конфигурации и время подтверждения; API-ключ не включать в snapshot и аналитику.

| Изменение | Требование |
|---|---|
| Новый provider или host API | Новое согласие до первого обращения |
| Добавлена роль | Согласие для добавленной роли и объединённого состава данных |
| Добавлена категория данных, описание или новый способ использования | Новое согласие, даже при прежнем provider |
| Модель изменена, может измениться фактический получатель | Обновить раскрытие и запросить согласие |
| Модель заменена у того же подтверждённого получателя, данные и условия неизменны | Обновить snapshot и явно показать модель; повторный полноценный экран не нужен, если адаптер доказывает неизменность условий |
| Ключ обновлён у прежнего адресата | Повторная проверка подключения; сама замена ключа не разрешает новые данные |
| Роль убрана | Разрешение сужается без дополнительных препятствий |
| Версия обязательного disclosure изменилась | «Нужно проверить передачу данных», запросы этой роли блокируются до подтверждения |

Перед каждым внешним вызовом gateway проверяет действительность согласия для этого вызова. Только UI-проверки недостаточно: операция может стартовать после восстановления приложения или в следующем этапе pipeline. Изменение настроек не разрешает автоматически отправить ранее неотправленную запись новому получателю.

### 7.4. Проверка соединения

Кнопка «Проверить подключение» не должна отправлять реальную последнюю заметку как тестовый промпт. Текущий JVM-клиент запрашивает список моделей; сохранить этот минимальный сценарий. Перед нажатием кратко объяснить, что ключ будет использован для обращения к указанному сервису. Если в будущем проверка включает inference, раскрыть тестовые данные и возможную платность до запуска.

Состояния: «Проверяем…», «Подключение доступно», «Не удалось проверить». Во время запроса отключена только повторная проверка и изменение отправляемых полей; Back доступен и отменяет ожидание там, где это поддержано. Timeout не означает «неверный ключ»: показать сетевую причину. Успех списка моделей не подтверждает работоспособность конкретной выбранной модели, наличие бюджета, STT и точность результата.

## 8. Ошибки, отзыв и восстановление PRIVACY-02

| Ситуация | Текст и действия | Что остаётся доступно |
|---|---|---|
| Нет сети при внешнем STT | «Нет связи с {provider}. Запись сохранена» только после подтверждения сохранения; «Повторить», «Выбрать обработку на устройстве» | Прослушивание реально сохранённого аудио и ручной текст |
| Нет сети при Text | «Не удалось обработать текст. Исходный текст сохранён» | Редактирование и сохранение исходного результата |
| Routing не ответил | «Не удалось предложить проект. Выберите его вручную» | Все допустимые направления сохранения |
| Ошибка авторизации | «Сервис не принял API-ключ», «Изменить подключение» | Локальные операции; данные не удаляются |
| Лимит/429 | «Сервис временно ограничил запросы»; время ожидания только по ответу сервиса | Отмена ожидания и локальная альтернатива |
| Модель отсутствует/недоступна | «Модель {id} недоступна для этой функции», «Выбрать модель» | Редактор исходника |
| Неверный адрес/ошибка TLS | «Не удалось безопасно подключиться к указанному адресу», «Проверить адрес» | Запрещено предлагать выключить проверку сертификата |
| Системное хранилище ключей недоступно | «Не удалось открыть защищённое хранилище ключа» | Локальная обработка; не сохранять ключ в обычный JSON в качестве обхода |
| Сервис вернул пустой/неприемлемый текст | «Сервис не вернул подходящий результат» | Сохранить исходник; не ставить пустой результат вместо него |
| Локальная альтернатива отсутствует | «Сначала скачайте модель или выберите доступный способ обработки» | Ручная работа и аудио; нет ложной команды «Обработать локально» без следующего шага |

Технические stack trace, ключи и необработанные тела ответов не выводятся пользователю. Сохраняется категория ошибки, роль, имя провайдера и безопасный correlation ID, если он нужен диагностике. Содержание текста/аудио не попадает в сообщение об ошибке.

### 8.1. Отключение сервиса

Подтверждение: «Отключить {provider}?», далее перечисление затронутых ролей. Если есть готовые локальные замены: «Для распознавания будет выбран {mechanism}; обработка текста потребует выбора модели» — по фактам. Кнопки «Отключить» и «Отмена»; destructive не маскировать словом «Готово».

После подтверждения новые отправки этому подключению запрещаются сразу; очищаются безопасные metadata соединения и ключ через платформенное хранилище. Не затронутые роли сохраняют выбор. Текущий код после удаления выставляет `DEFAULT_*`; целевой UI обязан проверить готовность этих defaults и не сообщать «Локальная обработка готова», если модель отсутствует.

Если есть выполняющийся запрос: попытаться остановить его и показать «Новые запросы остановлены. Уже отправленные данные могли быть получены сервисом». Отзыв не является удалением данных у провайдера. Не обещать, что запрос можно гарантированно отменить после передачи.

При ошибке удаления ключа соединение должно оставаться запрещённым для использования. Статус: «Сервис отключён, не удалось удалить сохранённый ключ» и команда повтора; не откатывать отзыв и не возобновлять отправки. Это требует отдельного платформенного результата удаления вместо предположения об успехе всего сценария.

### 8.2. Переход на локальную обработку

Открывает ту же страницу выбора роли с фильтром реально доступных механизмов. Если нужна загрузка — сначала загрузка и проверка, затем явная команда повтора обработки записи. Нет скрытого fallback в другой внешний сервис. Не загружать многогигабайтный пакет автоматически после сетевой ошибки.

Повтор уже обработанной записи не создаёт вторую заметку/задачу и не повторяет ранее завершённое распределение. Сохранить редактированный текст; запросить выбор «Использовать текущий текст» либо «Распознать запись заново» только если это действительно два разных действия в данном состоянии. Автоматический повтор внешнего запроса без ведома пользователя не включать при неоднозначном сетевом результате.

## 9. Разрешения устройства SETTINGS-05

Разрешения входят в «Приватность», а не открываются все подряд при старте. Системные диалоги ОС, календарь/время и выбор файлов используют системные элементы; запрет Material/SF Symbols относится к собственному продуктовому UI Kasha и не требует подменять разрешение ОС самодельным окном.

| Разрешение/возможность | Когда запрашивать | Отказ/ограничение |
|---|---|---|
| Микрофон | При первой явной записи или разрешённом сценарии автозапуска после объяснения | На Главной «Нет доступа к микрофону» и путь в настройки; остальные разделы работают |
| Системное распознавание речи | Перед первым использованием механизма, которому оно действительно требуется | Аудио не удаляется; доступен другой поддержанный механизм либо ручной текст |
| Уведомления | Когда пользователь впервые добавляет напоминание задаче | Задача сохраняется; «Напоминания выключены в настройках системы» рядом с расписанием |
| Возможность фонового исполнения | Только если платформа имеет соответствующий системный сценарий | Объяснить фактический режим; не делать фиктивный универсальный switch «Работать в фоне» |
| Защищённое хранилище ключей | При сохранении/использовании ключа, если ОС требует подтверждение | Состояние подключения объясняет невозможность доступа, без потери формы |

Список статусов: «Разрешено», «Не запрашивалось», «Запрещено», «Ограничено системой», «Не поддерживается». «Открыть настройки системы» отображается только при существующем платформенном переходе; иначе краткая инструкция для этой платформы, без неработающей кнопки. После возврата статусы перечитываются, но запись не стартует второй раз автоматически.

Запись и расшифровка — разные разрешения. Разрешённый микрофон не равен готовому системному распознаванию. Поддержка восьми языков интерфейса не равна поддержке Apple on-device STT для всех этих языков/устройств. При `onDeviceSpeechUnavailable` показать выбранный язык и «На этом устройстве распознавание этого языка недоступно»; не предлагать тайно передать аудио в сеть.

Статус уведомлений отделён от расписания задачи: «Срок установлен», «Напоминание запланировано», «Уведомления запрещены» — разные факты. Доставка может зависеть от ОС, режима фокусирования и состояния приложения. Для текущего PR iOS не показывать обещание повторов при полностью закрытом приложении, пока платформа не обеспечит следующее планирование. В desktop/web точную фразу о работе после закрытия брать из capability, а не переносить из iOS.

## 10. Интерфейс SETTINGS-06

### 10.1. Тема

Строка «Тема» открывает компактную страницу или sheet с тремя вариантами: «Как в системе», «Светлая», «Тёмная». Текущее `system` сохраняется по умолчанию; «тёмная — основная тема бренда» не означает молча менять системный выбор пользователя.

Каждый вариант — единая selectable row `minHeight=60 dp`, миниатюра 36×36 dp из настоящих tokens, текст 16/23, check 20 dp. Никаких фотографий внутри миниатюры. Выбор применяет тему ко всей поверхности, системным bar/icon brightness при поддержке и открытым sheets. Движение — краткий opacity-переход до 180 ms; при Reduce Motion без цветового перелива/масштаба.

Если выбрано «Как в системе», изменение ОС отслеживается без перезапуска и без потери текста, позиции списка, записи и focus. Индикаторы Recording/Paused остаются различимыми в обеих темах. Не менять тему лишь части экрана на кадр.

### 10.2. Язык

Первый пункт «Как в системе» с пояснением фактически выбранного языка; затем восемь имеющихся языков в текущем порядке `Languages`: Русский, English, Español, Français, Deutsch, Українська, Беларуская, Қазақша. Названия языков писать на их языке. Флаги не использовать.

Каждая строка минимум 56 dp, выбранная помечена check и semantic selected. Выбор применяет переводы сразу, не переименовывает пользовательские проекты, заметки и задачи. Возврат ведёт на то же место страницы настроек. При неизвестном системном языке действующая логика `Languages.resolve` использует английский; это нужно показывать честно в строке «Как в системе · English».

В текущем коде язык приложения также передаётся в операции распознавания. В тексте страницы раскрыть: «Этот язык также используется при распознавании, если выбранный способ поддерживает его». Отдельный селектор языка записи в данное ТЗ не добавляется без соответствующей модели настроек. Уже идущий запрос сохраняет язык своего старта; следующий использует новый.

Отсутствующий перевод не выводится ключом `aiConnectionOk` либо англоязычной технической ошибкой в русской сборке. Использовать установленный fallback каталога и регистрировать отсутствие перевода в проверке локализации. Все новые privacy-строки должны быть переведены на восемь языков до объявления полного покрытия.

## 11. О приложении SETTINGS-07

Спокойная страница с существующим solid-знаком шириной 64–80 dp, названием текстом только как обычной подписью приложения, не заменой логотипа, и фактической версией. Если build number отличается от public version, `Версия {version} ({build})` 14/20. Отметка демонстрационного/тестового режима видна здесь и там, где она меняет работу записи.

Допустимы страницы лицензий шрифта/моделей/зависимостей, если файлы присутствуют и открываются. Нельзя заполнять страницу выдуманными показателями устройства, «IQ модели», сравнением с чужими сервисами или статусом синхронизации, которой нет.

Диагностика — отдельное действие только при реализованном экспорте. Перед экспортом показать состав; исключить ключи, текст заметок, инструкции проектов и аудио по умолчанию. Автоматическая отправка диагностики не следует из выбора внешней AI-модели и требует собственного продуктового решения.

## 12. Приёмка настроек и приватности

- **SET-01:** установка темы, языка и движка с перекрывающимися сохранениями сохраняет все три последних значения после перезапуска.
- **SET-02:** `autoRecord` не создаёт запись при pending audio, существующем результате или повторном возврате из системного диалога.
- **SET-03:** четыре ступени качества и пять скоростей совпадают с моделью настроек; неподдерживаемая iOS-подготовка не изображается действующей.
- **SET-04:** переключение одной AI-роли не меняет две другие; общий пакет Text/Routing скачивается один раз.
- **SET-05:** выбранный `DEFAULT_*` с отсутствующим файлом не отображается Ready; недоступный runtime не скрывается за `defaultInstalled`.
- **SET-06:** iOS PR показывает Apple on-device и локальные правила, пока не подключены реальные role adapters; названия Whisper/Qwen не подставляются вместо фактического исполнения.
- **SET-07:** отказ микрофона/распознавания/уведомлений не удаляет аудио, текст или задачу; действия восстановления ведут к реальной платформенной возможности.
- **PRIV-01:** внешний вызов без действующего разрешения конкретной роли блокируется в gateway, включая восстановление после перезапуска.
- **PRIV-02:** consent Routing раскрывает текст, названия, описания, инструкции и ID проектов; payload не содержит иных личных данных.
- **PRIV-03:** замена endpoint/получателя или расширение данных требует обновлённого согласия; прежний ключ не отправляется на новый host автоматически.
- **PRIV-04:** тест соединения не отправляет личную запись; успех запроса моделей не подписывается «Все функции проверены».
- **PRIV-05:** ошибка внешнего STT оставляет реально сохранённое аудио; ошибка Text — исходный текст; ошибка Routing — ручной выбор.
- **PRIV-06:** отзыв останавливает новые запросы, не обещает удалить уже отправленное у провайдера, не заявляет готовность отсутствующей локальной модели.
- **PRIV-07:** ключ скрыт, не возвращается в Preferences, логи, clipboard автоматически или обычный JSON; ошибка secret store не включает небезопасный fallback.
- **SET-08:** вся длинная форма, ошибки и согласие проходят 320 dp, 200% текста, экранную клавиатуру и screen reader по [адаптивной приёмке](./07-adaptive-accessibility.md).
