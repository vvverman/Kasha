# 00. Решения, визуальные источники и границы

## 1. Образ продукта

Kasha — «тихая вычислительная машина для мыслей». Ощущение дорогого личного предмета создают материал, пропорции и последовательность действий. Приоритет внимания: **смысл пользователя → текущий процесс → доступное действие → фирменная атмосфера**.

Тёплый свет не должен делать приложение золотым. Большие пустые области не должны прятать управление. Кастомный контрол не должен терять узнаваемость или системную доступность. Эти три ограничения проверяются при каждой визуальной итерации.

## 2. Что именно берём из рисунков

| Наблюдение | Целевое применение |
|---|---|
| Тёплая почти чёрная среда | Canvas `#191715`, мягкое локальное освещение и низкий общий контраст декоративных слоёв |
| Светящийся материальный orb | Центральный объект захвата; процедурная поверхность, ограниченный bloom, реальная реакция на сигнал |
| Светлые мягкие кнопки | Песочный primary, крупная зона нажатия, сдержанная глубина, чёткий текст |
| Крупная асимметричная композиция | Один доминирующий объект; размеры и свободное пространство меняются по состоянию |
| Единая округлая нижняя панель | Одна поверхность навигации с четырьмя пунктами |
| Ненавязчивый плеер | Общий транспорт с развёрнутым и компактным представлениями одного состояния |
| Тактильные тёмные плоскости | Три уровня поверхности, без карточки вокруг каждого элемента |
| Макроматериал вне телефона | Дополнительный фон сплеш-экрана с гречкой по последнему уточнению пользователя |

Масштаб телефона, подписи вокруг него и рекламный коллаж не являются содержимым приложения. Приложение не рисует рамку iPhone, Dynamic Island или собственную системную строку состояния.

## 3. Реестр принятых решений

| ID | Решение | Причина и проверка |
|---|---|---|
| D-01 | Существующие `kasha_logo.svg` и `kasha_logo_solid.svg` сохраняются | Знак создан пользователем; сравнение исходных файлов по SHA-256 |
| D-02 | Текстовый serif-логотип на картинке заменяется официальным знаком | На экране нет имитации знака обычным текстом; текстовое название допустимо в заголовке системного окна и разделе «О приложении» |
| D-03 | Единственная гарнитура — Geologica Variable | Playfair/Inter на доске и Commissioner в коде описывают предыдущие решения |
| D-04 | Display отличается настройкой существующих осей и набором, а не второй гарнитурой | Не выдумывать `wdth`; точные оси и лицензия в основах |
| D-05 | Палитра из текста — исходная; AA обеспечивается семантическими вариантами | Не назначать светлый tertiary для важного мелкого текста только ради совпадения HEX |
| D-06 | Основной фон остаётся процедурным | Нет зависимости от загрузки большой картинки при запуске и записи |
| D-07 | Макросъёмка гречки разрешена как ограниченное дополнение | Последнее указание пользователя уточняет прежний запрет фотографий; только сплеш-экран; на Главной и во всех рабочих состояниях фотография запрещена |
| D-08 | Orb — живой UI-объект, не PNG | Реагирует на настоящие состояния и RMS; повторяет художественный характер референса |
| D-09 | Во время записи таймер и waveform важнее орба | Waveform может композиционно пересекать объект, но амплитуда читается и не прикрыта свечением |
| D-10 | Живой транскрипции в baseline нет | Картинка не доказывает существование streaming STT; показывать текст только по реальному capability и отдельной реализации |
| D-11 | «Расшифровываем», «Приводим в порядок», «Готовим текст» соответствуют этапам | Нет «магии», неясного «ИИ думает» и ложных процентов |
| D-12 | После результата — две самостоятельные команды | «В заметки» и «В задачи»; никакого `Note/Task` переключателя |
| D-13 | Один capture сохраняется в одну заметку либо одну задачу | Две кнопки не означают двойную публикацию или автоматическое дробление текста на задачи |
| D-14 | Один документ без поля названия | Первая непустая строка определяет title; новая первая строка обновляет списки |
| D-15 | Запись имеет один контроллер и одно интерактивное представление транспорта в текущем контексте | На Home транспорт развёрнут, в других вкладках компактный; не дублировать Pause/Stop рядом |
| D-16 | Навигация не останавливает запись | Возврат восстанавливает то же состояние; переход в Notes не создаёт новую сессию |
| D-17 | В idle запись начинается на Главной | Нет центрального FAB и лишнего Record на каждой вкладке; существующую возможность глобального idle Record требуется привести к этому правилу |
| D-18 | Главная не превращается в dashboard | Нет счётчиков, статистики, рекомендаций, аккаунта и маркетинговых карточек ради заполнения |
| D-19 | Текущий Kasha Icons остаётся единственной продуктовой библиотекой | Реестр/экспорты в этой документации задают следующую редакцию тех же glyph; runtime не получает второй pack |
| D-20 | AI-звёздочка `MAGIC` заменяется символом обработки текста | Узнаваемые действия вместо абстрактной «магии»; совместимость enum обеспечивается при миграции |
| D-21 | Сортировка — компактная команда с названием режима | Четыре постоянно видимых pills из нынешнего UI заменяются выбором в sheet/popover |
| D-22 | Закреплённые проекты всегда сверху, включая Manual | Это целевое изменение общего правила: `pinOrder` у закреплённых, `manualOrder` у остальных. Текущий Core в Manual использует общий порядок; изменение должно происходить в Core с миграцией/тестами |
| D-23 | Ручной порядок не теряется | Смена сортировки и pin/unpin не перезаписывают сохранённую пользовательскую расстановку; drag через границу групп не меняет pin неявно |
| D-24 | Повтор относится к напоминанию о той же задаче | Нет новых повторяющихся сущностей; автоматический перенос срока из Core сохраняется и объясняется |
| D-25 | В baseline срок и первое напоминание используют текущую модель | Не показывать независимое выключение/время напоминания, пока такой контракт не реализован; семантику `ReminderRepeat` не переименовывать в создание повторяющихся задач |
| D-26 | Поддерживаемость функции определяется реальным адаптером | `installed`, пункт каталога или выбранная Preference сами по себе не означают, что обработка доступна |
| D-27 | Внешний AI включается отдельно по роли с явным раскрытием данных | Смена провайдера/адреса/состава отправки пересматривает согласие; отключение не означает удаление уже отправленного у провайдера |
| D-28 | Production не выдаёт демо за работу AI | В iOS `main` есть заглушки; PR с адаптерами ещё не означает готовность всей цепочки |
| D-29 | Системные permissions, клавиатура, доступность, выбор файлов могут быть системными | Запрет стандартного внешнего вида относится к продуктовым компонентам; нельзя ломать ОС-диалоги ради стилизации |
| D-30 | Существующие функции, не нарисованные в референсе, сохраняются | Настройки модели, язык, append, pin заметки, архив, восстановление записи и приватность получают тот же дизайн |
| D-31 | Закреплённые заметки используют тот же целевой порядок групп, что проекты | Осознанное улучшение согласованности: pinned наверху, отдельные pinOrder/manualOrder; для ручного порядка закреплённых заметок нужен общий контракт, отсутствующий в текущем порте |

## 4. Информационная архитектура

| Раздел | Основной объект | Вложенные представления | Вход и возврат |
|---|---|---|---|
| Главная | Текущая запись/capture | Подтверждение отмены, обработка, текст результата, выбор назначения | Возврат сохраняет capture, текст, текущую стадию |
| Проекты | Упорядоченные проекты | Редактор проекта → заметки проекта → заметка и источники | Back возвращает в прежний список и позицию прокрутки |
| Задачи | Активные задачи | Задача, расписание, архив выполненных | Закрытие редактора возвращает в исходную выборку |
| Настройки | Предпочтения и возможности устройства | Аудио, роль AI, модель, внешний сервис, согласие, язык, тема, о приложении | Назад не отменяет уже сохранённую Preference |

Проектный picker при сохранении — временное представление потока Главной, а не переключение пользовательской сортировки экрана «Проекты». Рейтинг маршрутизации не перезаписывает обычный список.

## 5. Сохранность данных — часть UX

Нажатие «Завершить» закрывает запись, но не выбрасывает её содержимое. «Отменить запись» и «Отменить заметку» имеют конкретный объект удаления и требуют подтверждения. При ошибке интерфейс сообщает фактический результат: сохранён ли исходный файл, есть ли несохранённый текст, что можно повторить.

Визуальная анимация не является подтверждением транзакции. Кнопка не показывает успех до ответа общего workflow/хранилища. Быстрое двойное нажатие не создаёт дубль. Запоздавший AI-ответ не перезаписывает текст, который пользователь успел изменить.

Техническое сохранение незавершённого capture допускается и требуется для восстановления. Оно не создаёт в навигации разделы «Черновики», «Отложенные» или «Входящие».

## 6. Допустимые улучшения без расширения продукта

- Ясные состояния ошибки и повторного действия; возврат к исходному тексту после неудачной обработки.
- Прямое редактирование текста; сохранение выбора и курсора при обновлении оболочки.
- Отдельные семантические цвета для доступного текста и контуров.
- Доступная альтернатива drag через меню/клавиатуру.
- Подавление повторного запуска записи при возвращении из разрешений/фона.
- Явная маркировка ограниченной возможности адаптера вместо видимой неработающей кнопки.
- Сквозная спецификация motion и качественный анимированный каталог иконок.

Не добавляются аккаунты, синхронизация, команды, теги, приоритеты задач, чат с AI, статистика настроения, подписка, облачная БД и новые разделы из рекламной композиции.

## 7. Порядок разрешения новых расхождений

Разработчик сначала проверяет, является ли расхождение поведением данных или внешним видом. Внешний вид сверяется с этим комплектом; предметное правило — с `SPEC.md` и помеченными здесь целевыми изменениями. В PR описывается одно конкретное решение и его влияние на сохранённые данные. Нельзя локально обходить Core сортировкой, дублировать state в новом экране или менять согласие ради более короткого сценария.
