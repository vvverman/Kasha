# Локальные модели Kasha

Актуализировано 22 сентября 2026 года. Продуктовый контракт — [SPEC, раздел 7](SPEC.md#7-ai-pipeline). Старый комплект Whisper Small + Qwen3-4B больше не является штатной конфигурацией.

## Три независимые роли

| Роль | Модель | Движок JVM/Desktop | Приблизительный размер весов |
| --- | --- | --- | --- |
| `SPEECH_TO_TEXT` | Whisper Large-v3 Turbo Q5 | whisper.cpp, `whisper-cli` | 574 МБ |
| `TEXT` | Transcrib Cleanup 0.6B, Kasha GGUF Q4_K_M | llama.cpp, `llama-completion` | 397 МБ |
| `ROUTING` | F2LLM-v2 80M Q8_0 | llama.cpp, `llama-embedding` | 91 МБ |

В сумме это около 1,06 ГБ весов, а не размер установщика и не потребление оперативной памяти. Размер опубликованного `Kasha-Cleanup-0.6B-Q4_K_M.gguf` — **396 704 416 байт**. Предварительная оценка Cleanup в 347 МБ не соответствует этому опубликованному GGUF-файлу.

Единые идентификаторы, языки и отображаемые размеры определяет [KashaAiCatalog](../aiCatalog/src/commonMain/kotlin/brain/ai/KashaAiCatalog.kt). URL загрузок и обязательные SHA-256 определяет [ModelArtifacts](../aiCatalog/src/commonMain/kotlin/brain/ai/ModelArtifacts.kt). Core содержит контракты ролей, но не URL, веса и конкретные движки.

Каталог сейчас разрешает Cleanup для `ru`, `en`, `de`, `uk`, `pt`, `da`. Наличие языка интерфейса не означает поддержку этого языка каждой моделью. Неподдерживаемый язык должен отображаться как ограничение готовности роли, а не как успешная работа модели.

Выбор одинакового набора для платформ не заменяет отдельную проверку их нативных адаптеров, установки и фактического запуска моделей.

## Установка для локального Web/runtime и разработки

Запуск: `bash scripts/setup-models.sh`.

Скрипт собирает три CLI-цели из закреплённых исходников, загружает все три модели и публикует `models.env` только после успешной подготовки комплекта. Каталог по умолчанию — `~/.kasha-tools`, переопределение — `KASHA_TOOLS_HOME`. Для этого сборочного пути нужны `git`, `cmake`, `curl`, `ffmpeg`; его не следует путать с установкой готового desktop-приложения.

| Переменная | Назначение |
| --- | --- |
| `KASHA_WHISPER_CLI`, `KASHA_WHISPER_MODEL` | Исполняемый файл и веса транскрибации |
| `KASHA_LLAMA_CLI`, `KASHA_LLAMA_MODEL` | `llama-completion` и веса Cleanup |
| `KASHA_EMBEDDING_CLI`, `KASHA_ROUTING_MODEL` | Исполняемый файл и веса embeddings |
| `KASHA_FFMPEG` | Подготовка и проверка аудио |

Уже скачанные файлы с правильным SHA-256 используются повторно. Загрузка идёт в `.part`, затем проверяется сумма, и только после этого файл заменяет целевой. Ошибка контрольной суммы не заменяет прежний целевой файл и не публикует новый `models.env`. Пути экранируются для Bash, настройки создаются с доступом только владельцу. Установка не удаляет чужие или ранее загруженные модели.

Первичная подготовка требует интернета. Штатное локальное распознавание, нормализация и подбор проекта не требуют облачного API, ключа или аккаунта. Локальный HTTP runtime обслуживает Web UI на `127.0.0.1:8787`; это транспорт на том же устройстве, а не удалённый backend.

## Когда запускается каждая модель

После окончания записи STT получает подготовленную аудиокопию. Общий `CaptureWorkflow.finish` показывает транскрипт и завершает этот этап без обязательного запуска Cleanup или routing.

Над редактором находятся вкладки **«Транскрибация»** и **«Нормализация»**. По контракту нормализация запускается при первом открытии соответствующей вкладки; уже полученный результат используется повторно. Переключение вкладок само по себе не должно повторно запускать обработку.

Кнопка **«Обработать заново»** относится к активной вкладке: на транскрибации повторяет STT, на нормализации — Cleanup. Повторная транскрибация и изменение её текста сбрасывают устаревшую нормализацию и рейтинг проектов. Повтор Cleanup не требует нового STT. Команды «Привести в порядок» больше нет.

Данные двух вариантов не смешиваются: `transcript` хранит транскрибацию, `preparedText` — нормализацию, `selectedTextVariant` определяет вариант для сохранения. Автосохранение правки транскрибации нельзя проверять по `preparedText`: после такой правки устаревшая нормализация очищается.

Подбор проекта выполняет отдельный embedding-адаптер. Он сравнивает векторы текста и описания проекта, а не просит Cleanup генерировать рейтинг. Заголовок заметки выводится из первой непустой строки общим кодом — отдельной генерации заголовка нет. Добавление в существующую заметку не отправляет её прежнее содержимое на переписывание.

## Готовность, защита данных и ограничения

Пакет модели и исполняемый runtime проверяются отдельно для каждой роли. Отсутствие embeddings не делает STT или Cleanup неготовыми; наличие Cleanup не подменяет embedding-runtime. Старые настройки Qwen канонизируются с учётом роли: текстовая роль переходит на Cleanup, routing — на embeddings.

JVM probe запускает CLI с `--version`, а для STT дополнительно проверяет FFmpeg. Он не загружает веса и не передаёт пользовательский текст. Запросы моделей используют временные файлы: содержимое заметок не размещается непосредственно в списке аргументов процесса. Временные каталоги удаляются после завершения, ошибки или отмены.

Cleanup возвращает обычный текст; старая обязательная JSON-схема оформления к нему не применяется. Результат проходит проверки `LocalModelText.requirePreserved` и общего workflow. Это консервативные эвристики, а не доказательство смысловой эквивалентности. Распознавание может ошибаться, а нормализация не превращает ошибочный транскрипт в достоверный источник. Имена, числа, отрицания и самоисправления требуют отдельной проверки качества на живой речи.

Ошибки обработки не должны уничтожать доступные исходные данные или поздние ручные правки. Внешний AI остаётся отдельной возможностью с явным согласием; отсутствие локальной модели не является разрешением на скрытую отправку в облако.

## Проверки и статус

`python3 tests/setup_models_test.py` проверяет полный комплект, повторную установку, восстановление отсутствующего Cleanup и отказ при повреждённой загрузке. Проверяются соответствие production-пинов общему manifest, корректные export-пути, каталог с пробелами и сохранность предыдущих файлов. Сборочные и сетевые команды заменены тестовыми; SHA-256 вычисляется настоящим системным инструментом по маленьким фикстурам. Это проверка установки, **не запуск настоящих моделей**. Тест включён в `.github/workflows/model-setup.yml`.

`AiExecutionCapabilitiesTest` покрывает три отдельные роли, отсутствие пакета/runtime, legacy-настройки и безопасный probe. `tests/studio_browser.py` проверяет пользовательский сценарий с demo AI, включая автосохранение транскрибации и добавление в существующую заметку; он не подтверждает качество Whisper или Cleanup.

Workflow `models.yml` предназначен для сценария с настоящими моделями и изолированной сетью. Старые успешные отчёты Whisper Small/Qwen нельзя переносить на новый комплект. Для приёмки нужны результаты актуальной ревизии: сборки платформ, browser E2E и выполнение настоящих STT/Cleanup/routing.
