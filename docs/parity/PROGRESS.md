## Уточнение владельца: максимально общее Core с API приложения

Core предоставляет готовое поведение приложения, а не только модели и набор отдельных правил, из которых каждая оболочка заново собирает продукт. Цель — исправлять общее поведение в одном месте и максимально упростить сопровождение платформ.

1. В Core находится платформонезависимая координация сценариев: запуск и восстановление, запись/плеер и их взаимное исключение, обработка, сохранение, идемпотентность, задачи, порядок, применение настроек, privacy-проверки и защита от устаревших результатов.
2. Публичная граница предоставляет команды, запросы/наблюдение за актуальным состоянием и явные результаты операций. Потребители не редактируют доменные коллекции напрямую и не воспроизводят правила по отдельным полям.
3. API означает программный контракт. Не вводить обязательный HTTP-сервер, сеть или сериализацию для вызовов внутри нативного процесса. Разрешённый локальный Web transport при необходимости отображает тот же продуктовый контракт и не становится вторым ядром.
4. Core вызывает системные возможности через узкие порты; адаптеры возвращают факты и системные события. Core определяет продуктовые последствия, а не содержит проверки вида «если iOS, сохранить иначе».
5. Kasha UI остаётся одним общим слоем: экраны, компоненты, локализация, навигационное представление, фокус, анимации и адаптивная компоновка. Compose и визуальные детали не переносятся в Core ради процента общего кода.
6. Оболочка собирает зависимости, подключает Core и Kasha UI, передаёт системные события. Микрофон, permissions, файлы, уведомления, защищённое хранилище и упаковка остаются снаружи. Конкретные AI-провайдеры/модели и общий инфраструктурный код переиспользуются вне Core по SPEC, а не копируются по ОС.
7. Переиспользовать существующие контракты. Не добавлять второй параллельный API, универсальный framework, шину событий или плагины без конкретной необходимости. Общие правила не копировать даже при разных технических адаптерах.
8. Критерий: изменение правила заметки/задачи/записи требует одной общей правки и общих тестов, не шести правок оболочек. Пересборка выпусков и платформенные регрессионные проверки остаются обязательными. Новая ОС требует системных адаптеров и упаковки, но не новых экранов и пользовательских сценариев.

Новые тесты покрывают ошибку сохранения, изменение текста во время autosave/чтения/AI, отмену корутин, повторную публикацию, неизменяемый префикс append, запрет note+task, повтор старого receipt при другом current, жизненный цикл задач, сохранение настроек, независимость сортировки/manual/pin и наблюдение состояния без UI.

### Граница выполненного среза

Это начальный API контента, НЕ завершённое перемещение всего поведения в Core. В `StudioState` пока остаются запуск/autoRecord/recovery, транспорт и его polling, напоминания, демонстрационный запуск. Составное «сохранить рабочий текст задачи → выполнить» ещё находится в `TaskLifecycleActions.kt` и вызывает уже перенесённые базовые команды. AI-settings и device capabilities также требуют согласования со следующим API-срезом.

Защита новой редакции от позднего AI-ответа проверена на состоянии редактора в памяти. Полная транзакционная защита AI/хранилищ, работа при аварийном завершении и отсутствие долгого блокирования autosave во время AI не объявлены завершёнными этим переносом. `updatePreferences(transform)` работает с последним подтверждённым значением; перевод всех UI-обработчиков с целых копий Preferences на этот путь ещё нужен.
