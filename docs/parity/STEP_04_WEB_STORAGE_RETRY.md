# ТЗ 4.1 — Web: повторное чтение IndexedDB без потери аудио

## Исправление

`browser-platform.js` больше не кеширует отклонённый `indexedDB.open`. Повторный вызов после ошибки действительно открывает исходную базу. Успешное соединение переиспользуется; `close` и `versionchange` сбрасывают только своё соединение. `blocked` возвращает recoverable ошибку; позднее открытие заблокированного запроса закрывается и не подменяет новый connection.

Чтение журнала завершается только после `transaction.oncomplete`, не после `getAll.onsuccess`. Ошибка/abort транзакции запрещают продолжение `pendingSessions` и удаление якобы пустых журналов. Сам `pendingSessions` сделан строго read-only: успешное чтение пустой сессии также не разрешает её удаление, поскольку другая вкладка могла ещё не записать первый аудиофрагмент. Повторное пустое чтение chunks между обнаружением источника и upload также даёт ошибку без удаления исходной сессии. Отмена пользователем и очистка после подтверждённой передачи не меняются. Формат IndexedDB, Core и UI не изменены.

## Регрессии

`tests/web_storage_contract.test.cjs`: 12 проверок реального адаптера с управляемыми сбоями IndexedDB. На исходном адаптере: 2 passed, 8 failed, 2 cancelled. После исправления: 12 passed, 0 failed/cancelled/skipped. Существующие 12 контрактов Web-плеера также проходят. Дополнительно две регрессии чтения сессии до первого фрагмента: обе падали до удаления побочного cleanup и проходят после. Отдельная регрессия подтверждает сохранность исходных chunks при временной потере видимости между discovery и upload: падала до исправления. Итого 15 storage + 12 playback = 27 passed. Это Node-тесты границы, не браузерная приёмка.

`tests/web_storage_retry_browser.py`: production JS + настоящая IndexedDB в Chromium. Один ошибочный open через настоящий VersionError request, retry; настоящий abort после успешного getAll; сравнение всех исходных аудиобайтов и сохранность сессии, ожидающей первый фрагмент; закрытие процесса Chromium и запуск с тем же изолированным дисковым профилем; повторное чтение без дубликатов. Ошибки вводятся на границе browser API. AI и UI не участвуют. Результат записывается в `test-output/storage-retry/result.json`.

Оба набора включены в KMP CI. Браузерный результат нужно подтвердить на текущем head; локальный Chromium этой среды блокирует localhost, поэтому локальная синтаксическая проверка не выдается за browser PASS.

Закрывается конкретный дефект Web audio journal. Это не закрытие всего раздела 4: corrupt JSON, state/preferences barriers и остальные платформы требуют отдельной приёмки. Раздел 6 остаётся отложенным.
