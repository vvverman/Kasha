# Kasha 1.2.0 — кандидат на выпуск

Предрелиз для проверки приложения, не финальный выпуск для магазинов.
Все пакеты должны происходить из одной ревизии `main`, прошедшей восемь обязательных CI-процессов. Точный SHA, номера запусков, исходные артефакты и контрольные суммы находятся в `release-manifest.json`.

## Состав

| Платформа | Поставка | Ограничение |
|---|---|---|
| macOS Apple Silicon | DMG с автономным приложением, Java и локальными моделями | Developer ID и нотариальное заверение не подтверждены |
| Windows x64 | EXE либо MSI со всеми соседними CAB | Production-подпись не подтверждена |
| Linux x64 | DEB и RPM | Зависимости системных уведомлений/хранилища задаёт пакет |
| Android | Debug APK для установки; отдельно unsigned Release APK/AAB | Debug-подпись не является production-ключом; unsigned пакеты напрямую не устанавливаются |
| iOS | IPA для SideStore | SideStore подписывает пакет владельцем устройства; это не App Store/TestFlight |
| Web | Проверенные WebAssembly-ресурсы и локальный JVM runtime | Нужна Java 21; FFmpeg/AI-движки настраиваются отдельно. Это не автономный Desktop-пакет |

Версия приложения в Android/Desktop/iOS — 1.2.0. Android `versionCode` увеличен с 1 до 2. Канал предрелиза задаётся тегом `v1.2.0-rc.1`, а не подменой внутренних номеров версий уже собранных пакетов.

## Большие установщики

Из-за локальных моделей отдельные установщики превышают допустимый размер одного файла GitHub Releases. Они публикуются частями `.part001`, `.part002` и далее. Части — это байты исходного установщика, не отдельные архивы. Перед использованием их необходимо объединить и проверить.

### macOS — без установки дополнительных инструментов

Скачайте все части DMG и `assemble-macos.command` в одну папку. Откройте Терминал в этой папке и выполните:

```sh
bash assemble-macos.command
```

Сценарий проверит SHA-256 каждой части, соберёт DMG, проверит его итоговую сумму и откроет образ. Для этого используются только штатные `bash`, `cat`, `shasum` и `open`. Существующий отличный по содержимому DMG не перезаписывается. После установки дополнительные Java/Python/AI-инструменты для Desktop не требуются.

### Остальные платформы

Файлы без суффикса `.partNNN` уже готовы. Для MSI все CAB должны лежать рядом с исходными именами.

Для пакетов, разбитых на части, можно воспользоваться `restore-packages.py` (Python 3.11 или новее), положив рядом `release-manifest.json` и все части нужной платформы:

```sh
python3 restore-packages.py --platform windows-x64
python3 restore-packages.py --platform linux-x64
```

Помощник не скачивает данные, не запускает установщики и не удаляет части. Он проверяет их и не перезаписывает существующие отличающиеся файлы.

## Что проверено и что ещё требуется

Перед публикацией обязательны все восемь CI-процессов этой же ревизии: Core/UI/runtime/Web, Desktop adapters, Android shell, iOS Shared, SideStore, macOS installer, Windows/Linux packages и Android AI offline. При любой неуспешной или незавершённой проверке релиз не публикуется. Загруженные байты сверяются с digest CI-артефакта, затем с digest каждого файла Releases.

Физический микрофон, звонки, Bluetooth/AirPods и поведение на заблокированных устройствах остаются отдельной ручной приёмкой. Проверки вывода моделей не являются абсолютной гарантией сохранения смысла для любого текста.

Production signing/notarization этим выпускным процессом не выполняется. Перед стабильным выпуском нужны сертификат Developer ID и доступ к Apple notarization, Apple Team/provisioning для выбранного канала iOS и постоянный Android keystore. Нельзя подменять их случайным новым ключом или сохранять ключи/пароли в репозитории либо в чате.

## Повторный запуск

Публикация начинается как draft. При сбое он остаётся черновиком. Повтор того же SHA допускает уже загруженные файлы только при точном совпадении размера и SHA-256. Опубликованный релиз и существующий тег другой ревизии не перезаписываются. Для изменённого кода создаётся следующий RC-тег.
