Предыдущая диагностика `35706162383` / `025844b` показала потерю запрета удаления и окончательного дня при самокоррекции. Полные входы/ответы: [cleanup-probe-025844b.json](cleanup-probe-025844b.json).

Новая диагностика [35719261892](https://github.com/vvverman/Kasha/actions/runs/35719261892), `90b14bd`, artifact `10690562061`, SHA-256 ZIP **`288202b44bbe0ee6da2fb81f9d1799bffb7bf4c081b8a08947adefca54df3f6d`**.

Исходный MLX snapshot закреплён: `NicolaiMTLassen/transcrib-cleanup-0.6b`, ревизия **`881a17920f1a97e3adc155978188ad80c97bb0fb`**. Сохранены SHA-256 исходных файлов, версии пакетов, точные ChatML-входы и token IDs. Генерация выполняется при запрете внешней сети, GGUF предварительно проверяется по общему manifest.

Шесть GGUF-вызовов завершились с кодом 0, но не все ответы пригодны:

| Вход | Native-префикс без второго chat template | Явный upstream template без thinking |
| --- | --- | --- |
| Три предложения о записи, паузе и сохранении, включая «Старый текст удалять нельзя» | Последнее предложение с запретом исчезло | Последнее предложение с запретом исчезло |
| «Эээ, встреча завтра, нет, в среду в три часа» | Среда сохранилась, но ошибочное «завтра» тоже осталось | Среда исчезла, осталось «завтра» |
| «Ирина не меняла 1200 пунктов» | Текст сохранён | Текст сохранён |

**MLX в первом сравнении не сгенерировал ответы.** Все шесть вызовов остановились до генерации: `stream_generate` вошёл в Metal `wired_limit` при CPU-устройстве и получил `KeyError: max_recommended_working_set_size`. Это ошибка диагностического пути, не результат качества исходной модели.

Диагностика исправлена на публичный `generate_step` с тем же greedy sampler, теми же token IDs, лимитом 512 и остановкой по EOS. Сохраняются полные выходные токены. GPU-настройки памяти не вызываются; веса и пакеты не подменяются; запрет сети сохранён. Следующий запуск по умолчанию использует уже закреплённый snapshot, не новую ветку main. Синтаксис скрипта проверен локально; повтор генерации ещё требуется.

До получения обоих наборов завершённых ответов причина не разделена между моделью, преобразованием и протоколом. Даже различие MLX/GGUF потребует учитывать повторное квантование и происхождение исходного файла. Другую модель молча не подставляли. Защита Core отклоняет известные виды повреждения текста, но не доказывает полную смысловую эквивалентность и не делает некачественный ответ качественным.
